# 2 つの置き場

**旧マシンから新マシンへ何で運ぶか**で 2 つに分かれる。

| 置き場 | 置き場 | 運び方 | 新マシンでの復元 |
| --- | --- | --- | --- |
| **public** | `home/` | **git リポジトリ経由** | `git clone` で入る |
| **private** | `private/` | **暗号化アーカイブ経由**（`private_dotfiles.tar.gz.gpg`） | 復号して展開すると入る |

リポジトリは GitHub 上で public。**`home/` に置いたものは全世界から読める。**

## 置き場の選び方

**他人に見られて困るかどうか、だけ。**

| 問い | 置き場 |
| --- | --- |
| 公開して困らない（シェル設定・エディタ設定・汎用の規約） | **public** |
| 困る（資格情報・社内固有名・個人の情報） | **private** |

判断に迷ったら **private に倒す**。public から private へ移すのは、一度公開した事実を取り消せないぶん高くつく。

**秘匿値も private に入れる。** 以前は「値そのものが認証情報なら第 3 の置き場へ」としていたが、**private には既に SSH 秘密鍵とクラウドの資格情報が入っている**ので、API キーだけを別扱いしても守れるものがなかった。分けるべきだったのは中身ではなく、アーカイブに鍵を掛けることだった。

## アーカイブは暗号化する

`private/` は SSH 秘密鍵・AWS と GCP の資格情報・API キーを含む。**クラウドへ上げる前提なので、平文では置かない。**

```sh
tar czf - private | gpg --symmetric --cipher-algo AES256 > private_dotfiles.tar.gz.gpg
```

**パスフレーズはスクリプトが生成する。** 人が決めると弱くなり、二重入力も要る。`openssl rand -base64 24` の 32 文字で、バックアップ時に 1 度だけ表示する。

**`zip --encrypt` は使わない。** macOS 標準の `zip` が使うのは ZipCrypto で、既知平文攻撃が成立する 2007 年の方式。`gpg` の AES-256 に置き換えている。

**ファイルには書き出さない。** アーカイブと同じ場所に置くと、片方が漏れた時点で両方漏れる。パスワードマネージャへ保管し、これを失うとアーカイブは復元不能になる。

**バックアップは自分で叩く。** エージェント経由で走らせると、生成されたパスフレーズが会話ログに残る（`no_secret_values_in_output.md`）。

## そもそも管理しないもの

どちらの置き場にも入れない。**マシンを乗り換えたら捨てる**もの。

| 種類 | 例 | 理由 |
| --- | --- | --- |
| 会話・実行の記録 | `~/.claude/projects/`、`~/.claude/history.jsonl`、`~/.zsh_history` | 秘匿値が混ざりうるうえ、新マシンで必要にならない |
| キャッシュ・状態 | `~/.claude/{cache,sessions,shell-snapshots}`、`~/.npm`、`~/.cache` | 再生成される。zip が膨らむだけ |
| 揮発性のもの | ソケット、ログ、ロックファイル | 複製しても意味がない |
| **役目を終えたツールの設定** | `~/.qodo`（2026-04 以降未使用）、`~/.devdb`（定義が空）、`~/.gemini` | ユーザーが「使っていない」と確認済み。**再び使い始めたら取り込む** |
| 判定済みで対象外 | `~/.terraform.d`（checkpoint のみ）、`~/.cagent`（ハッシュ名のキャッシュ）、`~/.mcp-auth`（空） | 中身が設定ではない |

会話ログ (`~/.claude/projects/<プロジェクト>/<session-id>.jsonl`) は、**Claude とのやり取りが全文そのまま残る**。作業中に画面へ出た値も含まれるため、秘匿値と同じ扱いにする。

`~/.claude` は `PARTIAL_DIRS` により**子要素を明示的にリンクしたものだけ**が管理対象になる。これらは何もしなければ管理外に留まる。

**ホーム直下は全件を分類済み。** 新しいディレクトリが増えたら `/audit-dotfiles links` で拾い、この表のどこに当たるかを決める。**「判断がつかないから放置」を残さない**——次に見る人が同じ調査をやり直すことになる。

## 公開側への混入を止める

`scripts/git-hooks/pre-commit` が、ステージした公開側のファイルを検査してコミットを止める。`core.hooksPath` はリストア時に設定される。

| 検査 | パターンの置き場 | 理由 |
| --- | --- | --- |
| 認証情報 | フック本体（公開側） | `sk-ant-` 等は一般的な形式で、公開しても情報にならない |
| 非公開の固有名 | `private/.claude/deny-patterns.txt` | **パターン自体が社内固有名**なので公開側に持てない |

社内の呼称・リポジトリ名・GitHub ID が増えたら、パターンを足す。**グローバルの rules / skills は頻繁に書き換わり、複数のセッションが触る。** 規約だけでは取りこぼすので、git の境界で止める。

## 秘匿値の切り出し方

**設定ファイルに値を直書きせず、変数を参照する。**

```sh
# 悪い例: 値が設定ファイルに残る
alias ssml='curl -d "{\"api_key\": \"a107ad9e-...\"}" ...'

# 良い例: 値は ~/.secrets/env、ここは参照だけ
sesame() {
  curl -d "{\"api_key\": \"$SESAME_API_KEY\"}" ...
}
```

**エイリアスではなく関数にする**のが要点。エイリアスの本体は定義時に展開されるため、`alias ssml` の出力にキーが載る。関数なら実行時に読むので載らない。

変数を増やしたら `scripts/secrets.env.example` にも名前を足す。**アーカイブが手元に無い状況で何を埋めればよいか**が、ここだけを見て分かる状態を保つ。

## ~ へのリンクのされ方

`~` 側は実体を持たず、両方からリンクを張る。編集はリポジトリ内で完結し、`~` から集め直す工程が要らない。

```
~/.zshrc              -> home/.zshrc
~/.aws                -> private/.aws
~/.zsh_aliases        -> home/.zsh_aliases
~/.zsh_aliases_private -> private/.zsh_aliases_private
```

**public と private で同じ名前を使わない。** `link_layer home` の後に `link_layer private` が走るので、名前が衝突すると private 側が public を上書きし、公開エイリアスが読めなくなる。

### 丸ごとリンクしないディレクトリ

`~/.claude` `~/.codex` `~/.cursor` `~/.openclaw` `~/Library` は、管理対象と管理外（セッション・キャッシュ・OS の領域）が同居する。ディレクトリごとリンクすると管理外まで巻き込むため、**子要素を個別にリンクする**。

対象は `scripts/lib.sh` の `PARTIAL_DIRS` で定義する。ここに無いディレクトリの配下を管理下へ置くときは、まず追加する。**深い階層を管理するなら、途中のディレクトリも全部並べる**（`Library` → `Library/Application Support` → …）。

`~/.claude` 配下は `home/.claude/` に置いたものが自動でリンクされるので、資産の種類が増えてもスクリプトの変更は要らない。

| 資産 | 管理 |
| --- | --- |
| `CLAUDE.md` `rules/` `skills/` `hooks/` `settings.json` `statusline-command.sh` | する |
| `agents/` `output-styles/` | する（現時点では空） |
| `commands/` | **しない**。[skills に統合済み](https://code.claude.com/docs/en/skills)で、新規はすべて `skills/` に置くため空のまま |
