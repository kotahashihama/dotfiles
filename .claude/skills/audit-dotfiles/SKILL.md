管理下の設定は**壊れても静かに失敗する**。参照先が消えても、打つまで気づかない。種別ごとに見て、**直す・消す・入れ直す**のどれで畳むかをユーザーに選んでもらう。

引数で種別を指定できる。省略時は全種別を順に見る。

## 種別

### shell — エイリアス・関数・PATH

1. **実シェルから引く**。ファイルの `grep` だけだと入れ子のエイリアスと関数を取りこぼす

   ```sh
   zsh -ic 'alias'
   zsh -ic 'print -l ${(k)functions}'
   zsh -ic 'print -l ${(k)builtins} ${(k)commands}'
   ```

2. **自分で定義したものだけに絞る**。`home/.zsh_aliases/` `private/.zsh_aliases_private/` `home/.zshrc` に書かれている名前と突き合わせる。**Prezto が定義したエイリアスが 5 割を占める**ので、絞らないとノイズだらけになる

3. **参照先を辿る**。本体の先頭語を取り、それがエイリアスならさらに辿る。`sudo` `command` `noglob` `nocorrect` `env` は**前置修飾子**なので読み飛ばす（`nocorrect` を参照先と誤認しやすい）

4. **仕分ける**

   | 分類 | 意味 |
   | --- | --- |
   | 生存 | 参照先が存在する |
   | **欠落** | 参照先が無い。ツールを入れるか、定義を消すか |
   | 判定不可 | 変数展開・パイプ・相対パス。**実際に叩いて確かめる** |

5. **PATH も見る**。`PATH=/usr/bin:/bin zsh -ic 'echo $PATH'` で素の状態から起動し、重複と存在しないディレクトリを拾う。親シェルを継承すると重複が偽陽性になる

6. **起動時間**を測る（`/usr/bin/time -p zsh -ic exit`）。遅いときは二重ロードを疑う

### claude — ルール・スキル・フック

- **相互参照の切れ**: `## 関連` や本文が指すルール・スキルが実在するか
- **フックの参照先**: `settings.json` の `hooks` が指すスクリプトが存在し実行可能か
- **区分の重複**: `home/.claude/skills/` と `private/.claude/skills/` に同名が無いか
- **孤立**: どこからも参照されず、説明とも合わなくなった資産

### brew — Brewfile と実体

- `brew bundle check` で Brewfile の記載どおり入っているか
- **逆方向も見る**: 入っているのに Brewfile に無いものは、次のマシンで消える
- エイリアスが参照するツールが Brewfile にあるかを突き合わせる

### links — シンボリックリンク

- `~` のリンクが**切れていないか**（リンク先が存在するか）
- 管理対象なのに `~` が**実体のまま**になっていないか
- `home/` と `private/` で**同名が衝突**していないか

### secrets — 秘匿値

`/audit-secrets` に委譲する。ここでは `scripts/secrets.env.example` と `~/.secrets/env` の**変数名が一致しているか**だけを見る。ずれていると、新規マシンで何を埋めればよいか分からなくなる。

## 役目を終えたものを見分ける

**「参照先が無い」だけでは、入れ忘れなのか不要になったのか分からない。** 現状の構成と突き合わせて見立てを付け、**それを添えて尋ねる**。

| 手掛かり | 読み方 | 例 |
| --- | --- | --- |
| **後継ツールが入っている** | 移行済み。旧側は役目を終えている | `asdf` が無く `mise` が入っている → asdf 系は不要 |
| **Brewfile にも無い** | 入れ直す意思が無い。消す方向 | `php` が未インストールかつ Brewfile にも無い |
| **参照先がどこにも定義されていない** | 打ち間違いか、定義ごと消えた残骸 | `kts='kr 1'` の `kr` が存在しない |
| **文脈が変わった** | 前提そのものが無くなっている | 転職・プロジェクト終了で、その業務向けの定義が不要になる |
| **同じ役割が別名で生きている** | 重複。新しい側に寄せる | 旧ツールと新ツールで同じ操作のエイリアスが並存 |

**判断材料は会話から拾う。** 「もう使っていない」「〜に置き換えた」といった発言は、ファイルからは分からない最重要の情報。聞いていれば見立てに反映し、聞いていなければ**推測で消さずに尋ねる**。

見立ては `AskUserQuestion` の `description` に 1 行で書く。「未インストール」だけでは判断できず、「**後継に移行済みなので不要と見ています**」まで書いて初めて選べる。

## 進め方

1. 引数の種別（省略時は全種別）を順に実行する
2. **種別ごとに結果を出す**。全部終えてからまとめて出さない
3. 対応が要るものは **`AskUserQuestion` で 入れる / 消す / 保留 を選んでもらう**。似た性質のものはまとめて 1 問にしてよい
4. 選ばれた対応を実施し、**構文チェックと再読み込みで確認**する

## 出力の目安

種別ごとに件数を出し、**問題があるものだけ**を表で並べる。生存は件数のみでよい。

```markdown
### shell
生存 192 / 欠落 8 / 判定不可 16

| 定義 | 参照先 | Brewfile | 見立て |
| --- | --- | --- | --- |
| `goreshim` | `asdf` | 無し | mise へ移行済み。消すのが自然 |
| `kts` | `kr` | — | kr がどこにも無い。kt の打ち間違いか |
```

## やってはいけないこと

- ファイルを `grep` しただけで判定すること。**入れ子のエイリアスと関数を取りこぼす**
- Prezto 等が定義したものを混ぜること。**ユーザーが管理していないものを消す提案をしない**
- 判定不可を「欠落」に混ぜること。相対パスや変数展開は、その場では動く
- 確認なしに**定義を消す / ツールを入れる**こと（`decide_or_ask.md`）
- 非公開区分の定義を公開区分のファイルへ移すこと（`.claude/rules/file-placement.md`）
