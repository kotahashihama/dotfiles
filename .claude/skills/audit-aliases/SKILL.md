エイリアスは**壊れても静かに失敗する**。打った瞬間に `command not found` が出るまで気づかないため、定期的に棚卸しする。定義は `home/.zsh_aliases/`（公開）と `private/.zsh_aliases_private/`（非公開）に分かれている。

## 進め方

1. **定義を集める**: 実シェルから引く。ファイルを読むだけだと、入れ子のエイリアス展開や関数を取りこぼす

   ```sh
   zsh -ic 'alias' | sed -E "s/^([^=]+)=.*/\1/"
   zsh -ic 'print -l ${(k)functions}'
   ```

2. **参照先のコマンドを抜く**: 各定義の**本体の先頭語**を取る。`alias tfi='tf init'` のように**エイリアスがエイリアスを参照する**ことがあるので、解決できるまで辿る。`$VAR` で始まるものや `.` / `source` は対象外

3. **死活を判定する**: `command -v <cmd>` で存在を見る。エイリアス名・関数名・シェル組み込みに一致するものは生存扱い

4. **結果を 3 つに仕分ける**

   | 分類 | 意味 |
   | --- | --- |
   | **生存** | 参照先が入っている |
   | **欠落** | 参照先が入っていない。ツールを入れるか、定義を消すか |
   | **判定不可** | 変数展開・複雑な引用で先頭語が取れない。目視で確認する |

5. **欠落したものは Brewfile と突き合わせる**: `Brewfile` に記載があるなら「入れ忘れ」、無いなら「もう使っていない」の可能性が高い。この見立てを添えると判断が速い

6. **`AskUserQuestion` で対応を尋ねる**: 欠落したものごとに **入れる / 消す / 保留** を選んでもらう。似た性質のものはまとめて 1 問にしてよい

7. **選ばれた対応を実施する**

   | 選択 | やること |
   | --- | --- |
   | 入れる | `brew install <formula>` し、`Brewfile` にも追記する |
   | 消す | 定義を削除する。**どちらの層のファイルか**を確認してから触る |
   | 保留 | 何もしない。次回また出ることを伝える |

8. **消したら再読み込みして確認する**: `zsh -n` で構文を見て、`zsh -ic` で残った定義が引けることを確かめる

## 出力の目安

分類ごとに件数を出し、**欠落と判定不可だけ**を表で並べる。生存は件数のみでよい。

```markdown
| 定義 | 参照先 | Brewfile | 見立て |
| --- | --- | --- | --- |
| `ghqg` | `ghq` | あり | 入れ忘れ。入れるのが自然 |
| `nuxt` | `./node_modules/.bin/nuxt` | — | プロジェクト内前提。判定不可 |
```

## やってはいけないこと

- ファイルを `grep` しただけで判定すること。**入れ子のエイリアスと関数を取りこぼす**
- 欠落を見つけて、**確認なしに定義を消す / ツールを入れる**こと。どちらもユーザーの判断（`decide_or_ask.md`）
- 判定不可を「欠落」に混ぜること。プロジェクト内のパスを参照するものは、そのディレクトリでは動く
- 非公開層の定義を、公開層のファイルへ移すこと（`.claude/rules/layer-placement.md`）
