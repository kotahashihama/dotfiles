# ファイルは public / private / secret のどれかに置く

置き場ごとに公開範囲と復元方法が決まる。**このリポジトリは GitHub 上で public** なので、`home/` に置いたものは全世界から読める。

層の定義・選び方・秘匿値の切り出し方は [`docs/layers.md`](../../docs/layers.md) を読むこと。

## 期待する挙動

- ファイルを追加・移動する前に、`docs/layers.md` の判断表でどの層かを決める
- 迷ったら **private に倒す**。後から public へ上げるのは容易、逆は取り返しがつかない
- 秘匿値は設定ファイルへ直書きせず `~/.secrets/env` へ置き、参照だけを残す
- 秘匿値の変数を増やしたら `scripts/secrets.env.example` にも名前を足す
- `~` へ取り込むときは `./scripts/adopt_dotfile.sh {public|private} <path>` を使う。手で `mv` + `ln` しない

## 禁止する挙動

- **`private/` を追跡対象にすること**。`.gitignore` の `/private/` を消す・例外を足すのは、内容を 1 件ずつ確認したうえでの意図的な公開に限る
- 秘匿値を含むファイルを `home/` へ置くこと
- `home/` と `private/` で **同じ名前を使うこと**。private 側が public を上書きし、公開設定が読めなくなる
- コミット前に公開層の差分を確認せずに済ませること

## コミット前の確認

`home/` と `scripts/` の差分に秘匿値が混ざっていないかを毎回見る。手順は `/audit-secrets` が持つ。

履歴に入ってしまった場合は、**その場で報告して指示を仰ぐ**。`reset --soft` での履歴書き換えと force push はユーザーの判断事項。

## なぜ

- 公開リポジトリは「間違えて置いた」が取り消せない。push した時点で第三者のクローンやキャッシュに残りうる
- private を 1 つの zip に固めてクラウドへ上げる運用のため、**秘匿値を private に置くと卵を 1 つのカゴに入れることになる**。層を 3 つに割るのはこのカゴを分ける操作
- 置き場のルールが曖昧だと、追加のたびに判断が揺れる。判断表を 1 箇所に置けば、迷いが「表を見る」に変わる

## 関連
