# 管理対象ファイルにバックアップ・リストアの文脈を書かない

`home/` と `private/` に置くのは **設定ファイルそのもの**。それが git で運ばれるのか暗号化アーカイブで運ばれるのか、新規マシンでどう復元されるのかは、**このリポジトリの都合**であって設定ファイルの関心事ではない。

## 禁止する記述

- 「暗号化アーカイブに含める」「git には入れない」等の、**どの層に属するかの説明**
- 「新規マシンでリストア前でも起動できるよう」等の、**復元手順を前提にした説明**
- 「gitignore 済み」「バックアップ対象」等、リポジトリ運用への言及

```sh
# 悪い例
# 非公開エイリアス（暗号化アーカイブに含める。git には入れない）
. ~/.zsh_aliases_private/project.zsh

# 良い例
# 非公開分
. ~/.zsh_aliases_private/project.zsh
```

## 期待する記述

- そのファイルを**設定ファイルとして読む人**に必要なことだけを書く
- コードから読み取れない実装判断は書いてよい（例: エイリアスではなく関数にした理由）
- 層や復元手順の知識は `docs/layers.md`・`scripts/`・`README.md` に置く

## なぜ

- 設定ファイルは `~` にリンクされて**日常的に読み書きされる**。運用メモが混ざると、設定を探すたびにノイズを読まされる
- 運用が変わったとき、**設定ファイル側の記述が取り残されて嘘になる**。zip の名前を変えただけで、あちこちのコメントが古くなる
- 層の情報は置き場所そのものが表している。`private/` にあるファイルに「これは非公開です」と書くのは重複

## 例外

- `scripts/` 配下は運用の実装そのものなので対象外。層や復元手順を書いてよい
- `scripts/secrets.env.example` は雛形であり、埋め方の案内を書いてよい

## 関連

- `layer-placement.md`（層の選び方）: どこに置くかを規定する。本ルールは置いたファイルに何を書かないか
