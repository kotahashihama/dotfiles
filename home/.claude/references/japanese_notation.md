# 日本語の表記：数値と単位・空白・約物・ダッシュ

会話・ファイル・投稿のどこに書く日本語にも当てる表記の規定の詳細。要点は常駐のルール `rules/japanese_notation.md` が持ち、フックが守らせている。
判定は `~/.claude/hooks/check-japanese-spacing.py` が持ち、`stop-checks.sh`（会話と書いたファイル）・`lint-github-body.sh`（`gh` の投稿）・`require-review-before-post.sh`（MCP と bee の投稿）が呼ぶ。差し戻しの理由を詳しく知りたいときに開く。

## 数値と単位のあいだに空白を入れない


日本語の文章では、数値と単位・助数詞をくっつけて書いてください。
会話・PR 説明・コミット・レビューコメント・ドキュメント、こちらが書くものすべてが対象です。
これは全プロジェクト共通の規約です。

```
❌ 2 万件 / 21 秒 / 885 MB / 11.2 倍 / 3 ファイル / 1 行
✅ 2万件 / 21秒 / 885MB / 11.2倍 / 3ファイル / 1行
```

### 対象

**数を数えている語すべて。** 助数詞（件・秒・倍・行・本・回・個・人・箇所）も、記号の単位（MB・GB・ms・MiB・vCPU）も同じ扱いです。

| くっつける | 例 |
| --- | --- |
| 助数詞 | `70,000件` `9分45秒` `11.2倍` `3本` |
| 単位記号 | `885MB` `0.688ms` `13.28MiB` `2048MB` |
| 割合 | `93.9%` `-4%` |

桁区切りのカンマはそのまま。`70,000件` のように、数値の中の書式は変えません。

**会話への応答で最も崩れます。** 書く量が一番多いのもここ。応答は Stop フックが検査し、外れていれば止めて直させます（ `require-japanese-response.sh` 。止める回数は Stop フック全体で1プロンプトにつき3回まで）。止まってから直すのは手戻りなので、書く時点で守る。

### 対象外

| そのまま | 理由 |
| --- | --- |
| コード・識別子・コマンド | `memory = 2048` `--limit 10` は元の書式が正 |
| 引用・ログの原文 | 原文を書き換えない |
| 英語の文章 | 英語圏の慣習（ `21 s` ）に従う |
| 数と単位が係り受けで離れているとき | 「3つのうち2つ」の「うち」は単位ではない |

### 英語と日本語のあいだには、逆に空白を入れる

紛らわしいので分けて覚える。空白を詰めるのは数値と単位のあいだだけで、英字と日本語のあいだは空けます。

```
✅ 885MBのメモリ         ← 数量はひとかたまり。前後の日本語とも詰める
✅ 1.06msで安定している
✅ Aurora が接続を切る    ← 純粋な英単語は日本語と空ける
❌ 885MB のメモリ
❌ Auroraが接続を切る
```

| 境界 | 空白 |
| --- | --- |
| 数値 ↔ 単位・助数詞 | 入れない |
| 日本語 ↔ 数字 | 入れない（ `が20000件` `全8回` ） |
| 英字 ↔ 日本語 | 入れる |
| 数量（数値＋単位）↔ 日本語 | 入れない（ `885MBのメモリ` `1.06msで` ） |
| 混ざった語 ↔ 日本語 | 入れない（ `はJR東日本も` ） |
| 全角の約物 ↔ 英字 | 入れない（囲む・区切るのどちらも。下記） |

**空白を入れるのは、独立した英単語と日本語が隣り合うときだけ。** 数量（数値＋単位）は日本語と直接くっつきます。

**判定は「数量か、語か」。** `885MB` は1つの量なので、前後の日本語ともくっつけます。`Aurora` は語なので空けます。

単位だけを見て英字と判定しない。`ms` は英字ですが `1.06ms` の一部であって、独立した語ではありません。

語の中で英字と日本語が混ざっているなら、その語も前後と詰めます。判定は語の内側をどう書いたかで、英字に日本語をくっつけたなら一かたまり、英字を独立させたなら両側を空ける。

```
❌ 応募意思は JR東日本も保持している
✅ 応募意思はJR東日本も保持している
✅ そちらは Aurora が接続を切る       ← 英字が独立しているので両側を空ける
```

範囲の `〜` は語の一部に数えません（ `対象は v2〜v3` ）。区切りの記号なので、前の英字とひとかたまりになりません。

```
✅ 更新が20000件 / 全8回 / 885MBのメモリ / 1.06msで安定 / Aurora が接続を切る
❌ 更新が 20000件 / 全 8回 / 885MB のメモリ / 1.06ms で安定 / Auroraが接続を切る
```

#### 全角の約物との境界には空白を入れない

**囲む約物も区切る約物も同じ扱いです。** 全角の約物はそれ自体に余白を持っているので、足すと空きすぎます。

```
✅ 「変更履歴」hoge  、hoge  。hoge  （hoge）  【hoge】
❌ 「変更履歴」 hoge  、 hoge  。 hoge  （ hoge ）
```

対象は `、` `。` `「` `」` `・` `？` `！` `（` `）` `【` `】` など。

中身が英字か日本語かで変えない。`（生成者表示の NOTE は数えない）` のように混ざるのが実際の書かれ方で、どこまでを英字と見るかが決まりません。

半角の約物は対象外。`(hoge)` は元から余白が狭いので、そのまま書きます。

半角スラッシュも対象外。`A / B` は選択肢を並べる記号なので、両側に空白を置く。詰めると `」/ 「` になり、区切りが約物に飲まれて読めなくなります。

#### インラインコードの前後は空ける

**約物よりインラインコードのほうが優先します。** 背景色が付くので、隣と接すると詰まって見えます。

```
✅ 変更履歴の `change_history_ms` は重い
✅ 親（ `accounts` ）の行数
❌ 変更履歴の`change_history_ms`は重い
❌ 親（`accounts`）の行数
```

**句読点の直前だけは詰める。** ここに空白を置くと、句点が浮いて見えます。

```
✅ 値は `null` になる。
❌ 値は `null` 。
```

「全角の約物の内側は空けない」を上書きします。ルール群で数えると、内側がインラインコードのものは94対0で詰めていましたが、背景色が接する事情はコードにしか無いので例外にします。

### なぜ

- **空白があると1語に見えない。** 「2万件」は読むときに一度分解が入る。数と単位はひとかたまりの情報なので、見た目もひとかたまりにする
- 日本語の組版では数値と助数詞のあいだに空白を置かないのが通例。空白を入れるのは英語の慣習で、混ぜると表記が揺れる
- 表のセルでは特に差が出る。空白が入ると折り返し位置が増え、狭い列で不自然に改行される
- 全角の約物を「英字なら空ける」としていた時期があったが、実例が0件だった。ルール群52本で内側を空けていたのはこの規約自身の OK 例1件だけで、他の213件はすべて詰めている。基準が使われていないなら、基準のほうが誤っている

### 例外

- ユーザーが特定の表記を指定した場合
- そのリポジトリの既存文書が空白ありで統一されている場合は、そのファイルの中では既存に合わせる（1つの文書で表記が割れるほうが読みにくい）


## 日本語の文章にダッシュを使わない


`——` （全角ダッシュ）や `--` を、文の途中で言い直し・補足・言いさしを表すために使わないでください。
会話・PR 説明・コミット・レビューコメント・ドキュメント、こちらが書くものすべてが対象です。
これは全プロジェクト共通の規約です。

```
❌ 件数では説明できない——2万件が落ち、10万件が通っている
✅ 件数では説明できない。2万件が落ち、10万件が通っている

❌ 判定は読み手の側——書き手が誠実に感じても意味はない
✅ 判定は読み手の側にある。書き手が誠実に感じても意味はない
```

### 言い換え方

ダッシュは3つの役目を兼ねています。どれを担わせていたかで置き換え先が変わります。

| ダッシュの役目 | 置き換え |
| --- | --- |
| 根拠・具体例を足す | 句点で切って次の文にする。「〜。〜」 |
| 言い換える | 「つまり」「言い換えると」を使うか、片方を消す |
| 補足を挟む | 括弧に入れるか、次の文へ出す |

**多くは句点で切れば済みます。** ダッシュを使いたくなるのは1文に2つのことを詰めているときなので、分ければ解決する。

### 対象外

| そのまま | 例 |
| --- | --- |
| コマンド・オプション | `--region` `-batch` |
| 範囲の表記 | `364〜378MB` （波ダッシュは別物） |
| 表の区切り | `\| --- \|` |
| 引用・ログの原文 | 原文を書き換えない |
| 英語の文章 | 英語圏の慣習に従う |

### なぜ

- **書き手には勢いがあるが、読み手には切れ目が見えない。** 日本語は句読点で構造を示すので、ダッシュが挟まるとどこまでが1つの主張かを組み立て直すことになる
- 1文に2つのことを詰める癖の表れでもある。分ければ、どちらの文も短くなって読みやすい
- 全角ダッシュは環境によって見た目が揺れる（ `—` `―` `–` の判別がつかない）

### 例外

- ユーザーがダッシュを使った文面を指定した場合
