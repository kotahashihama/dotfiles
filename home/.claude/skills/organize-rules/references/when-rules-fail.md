本体の「守られなかったときは、型で当たる」から開く。守られなかったルールを直すときだけ要る。

## 守られなかったときは、5つの型で当たる

**逸脱はルール側の欠陥を示す信号です**（本体の「整理の契機」）。原因は次の5つに分かれ、**直す場所がそれぞれ違います**。

| 型 | 症状 | 直し方 |
| --- | --- | --- |
| **手順が無い** | 何を書くかは分かるが、**いつ書くか**が決まらない | 順序を書く（本体の「対応するスキルが無いルールは、自分で手順を持つ」） |
| **記憶に依存している** | 「〜したとき」「前回〜なら」で条件を書いている | **その場で引ける形へ**（API・ファイル・コマンド） |
| **本則が読まれない位置にある** | 手前で判定手順が完結し、その先へ辿り着かない | **本則を冒頭へ出す**。節タイトルが本則と逆を向いていないか見る |
| **本文だけで効かない** | 規定はあるが、実行時に思い出せない | **`## 禁止する挙動` へも名指しで置く** |
| **数量の単位が書かれていない** | 「1度だけ」「毎回」「N 件まで」の**何につき**が抜けている | **単位を書く**（1 PR につき / 1相手につき / 1セッションにつき） |

**5つ目は、書いた側と読む側で単位が食い違います。** 「総括で1度だけ開く」を「1 PR につき1度」と読み、**同じ相手へ3本連続で出して**ようやく気づいた例があります。書いた側は「1相手につき」の意図でした。

**2つ目が最も見つけにくい。** 「対応後にもう一度呼ばれたとき」のような条件は自然に読めますが、**セッションが変われば前回を覚えていません**。**同じコマンドをいつ打っても同じように動くか**で判定する。

**4つ目は重複に見えます。** ところが本文は説明の流れの中にあり、`## 禁止する挙動` は**逸脱の一覧として引かれる**。役割が違うので、両方に置いてよい。

**判定の問いは「逸脱したとき、自分はどの節を開いていたか」。** その節に無ければ、そこへ置く。

**手順を順に辿る形の資産では、前半の節は通り過ぎた後です。** 投稿や実行の直前に開くのは、その段の手順と `## 禁止する挙動` だけ。**規約を読む段に書いてあっても、手を動かす段では視界に入っていません。**

## 6つ目。文章を直しても止まらないなら、フックへ寄せる

**上の5つはすべて「書き方を直す」型です。** 直しても守られないなら規約の側ではなく置き場を疑う。

**フックより上の段で止められないかも見る。** 構造で起きなくする、型で書けなくする、検査で落とす、テストで捕まえる、文章で頼む、の順に強く、文章は何も止めません。上の段から探す手順は `/pstack:correct` が持ちます。文章で頼むしかないときの書き方（目立たせて、失敗の例を添える）は `principle-encode-lessons-in-structure` が持ちます。手元の資産でフックまで降りるのは、上の段が使えないとき（会話の書き方のように、構造も型も無い対象）です。

| 見るもの | フックへ寄せる合図 |
| --- | --- |
| **判断が挟まる段があるか** | 「読む」と「守る」の間に「検査を回す」が入る。**そこで落ちる** |
| **出力が取り消せるか** | 外部へ出た後は、消しても記録が残る |
| **形だけで判定できるか** | 文字列やコマンドの形で決まるなら書ける |
| **書いた本人が直後に破ったか** | **手癖のほうが速い。** 思い出せないのではなく、思い出せるのに破る |

**1つ目が本体です。** 規約を読むのに判断は要らず、フックが弾くのにも要らない。**あいだの「検査を回す」だけに判断が挟まり、そこで落ちます。**

**4つ目は、上の5つの型で言う「本文だけで効かない」と対処が同じですが、症状が逆です。** あちらは実行時に思い出せない。こちらは**思い出せるのに破る**。禁止を書いた直後に自分が破ったなら、**文章を足しても止まりません**。

実際に、書式の規約を毎セッション全文読んだうえで投稿した PR 本文30件が、**30件とも違反**していました。同じ日に、投稿前に検査を回した3本は0件。**差は「回すと判断したか」の1段だけ**で、フックにするとその段が消えます。

**寄せる前に、過去の実出力へ当てて測る。** 違反が出ないならフックは要らないし、出た指摘が誤検知なら判定条件のほうが誤っている。

**測るのは「検査を回さなかった出力」だけ。** 回した分を混ぜると要否そのものが測れません。上の例では、同じ規約・同じ検査条件で**正反対の結論**が出ます。

| 測った範囲 | 違反 | 出る結論 |
| --- | --- | --- |
| 検査を回した3本 | 0/3 | **要らない** |
| 回さなかった30件 | 30/30 | 要る |

**回した分が0件なのは、そのとき回したからです。** フックが埋めるのは「回すと判断しなかったとき」の穴なので、**判断が働いた出力はサンプルに選べません**。分けられないなら、検査の習慣が付く前の期間で切る。

**測る対象が1種類に偏っていないか見る。** 上の30件では PR テンプレートの HTML コメントによる誤検知が0件でしたが、**テンプレが全部英語だっただけ**でした。日本語のコメントで試すと弾きます。**件数が正しくても、探索範囲が覆っていなければ誤検知は出ないまま残ります**（ `verify_the_check_worked.md` ）。

**フックにしても規約は消さない。** deny の理由は結局その規約の文章で、消すと「ブロックされました」しか残りません。**フックが捕まえるのは列挙した形だけ**なので、書いていない形はルールが受け持ちます。
