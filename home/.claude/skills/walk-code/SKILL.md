コードを**一緒に辿る**ウォークスルーです。起点から目的地まで**1 区切りずつ進み、各区切りで止まって**次を尋ねます。

**説明だけを行い、コードは書き換えません。**

## 一度に渡さないのが要点

**兄弟スキルとの違いは「渡し方」です。** 説明する内容ではありません。

| | 渡し方 | 進路を決めるのは |
| --- | --- | --- |
| `/break-down` | **一度に**（図と表で俯瞰） | こちら |
| `/explain-code` | **一度に**（順に読み下す） | こちら |
| **本スキル** | **1 区切りずつ、止まりながら** | **ユーザー** |

**同じコードでも、辿りたい人には一括で渡さないほうが入ります。** 読み手は自分のペースで進み、途中で「そこ詳しく」「戻って」「そこは飛ばして」と進路を変えられる。

**一度に全部出したくなったら、それは `/explain-code` の仕事です。**

## 対象

| 起点 | 追うもの |
| --- | --- |
| **エンドポイント・画面操作** | リクエストが層を通って戻るまで |
| **関数・メソッド** | そこから呼ばれる先へ、depth 順に |
| **値・データ** | どこで作られ、どう変換され、どこへ保存されるか |
| **不具合の症状** | 症状から原因へ、逆向きに辿る |

第 2 引数で**目的地**を指定できる（「保存されるところまで」「レスポンスが組み立たるところまで」）。

## 進め方

### 1. 起点と目的地を決めてから歩き出す

**どこへ向かうか決めずに始めると、辿るうちに目的が曖昧になります。** 最初に確かめる。

- 起点が曖昧なら**先に尋ねる**。「この API を叩いたとき」「この関数が呼ばれたとき」まで絞る
- 目的地が言われていなければ**こちらで置いて、冒頭で宣言する**。「保存が確定するところまで見ます」
- **不具合を追うなら、症状のほうを目的地にする。** 起点は「どこから逆に辿るか」

### 2. 経路の地図を先に出す

**歩き出す前に、全体で何区切りあるかを渡す。** 現在地が分かるようにするためで、**内容の説明ではありません**。

- **3〜8 区切り。** それ以上なら目的地が遠すぎるので、途中で区切り直す
- **各区切りは 1 行**（「① 受け口でリクエストを検証する」）。中身はまだ書かない
- 経路が枝分かれするなら `flowchart` を 1 つ。**枝が無いなら箇条書きで足りる**

### 3. 1 区切りずつ進む

**各区切りで出すものを固定する。** 形が毎回同じだと、読み手は現在地を見失いません。

| 順 | 出すもの |
| --- | --- |
| 1 | **今どこか**（「② 保存する形へ組み替える」＋ `file:line`） |
| 2 | **抜粋 5〜20 行。** 省いた所は `// ...` |
| 3 | **何が起きたか**を 2〜5 行。入ってきた値がどう変わったか |
| 4 | **次はどこへ行くか**を 1 行。なぜそこへ移るのか |

**値を持ち回る。** 「ここで受け取った UUID が、次はこの引数に入ります」と繋ぐと、区切りが分断されません。**ウォークスルーの価値はこの連続性**にあります。

**文法・言語機能は、その場で 2〜4 行だけ開く**（`plain_language_explanation.md` と `CLAUDE.md` の習熟度）。詰まったまま次へ進ませない。

### 4. 区切りごとに止まる

**進む前に必ず止まる。** これが本スキルの核で、守らないと `/explain-code` と同じものになります。

- 各区切りの末尾で「**次へ進みますか / ここを掘りますか**」を出す
- 選択肢が 2 つ以上あるなら **`AskUserQuestion`**（`decide_or_ask.md`）。地の文の問いかけは読み飛ばされる
- **黙って次へ進まない。** 3 区切りまとめて出したら、それは一括で渡している

**ユーザーが「全部いって」と言えば止まらずに進む。** そのときは `/explain-code` の形に切り替わったものとして扱う。

### 5. 寄り道に応じる

**進路はユーザーが決めます。** 求められたら現在地を離れてよい。

| 求められること | 応じ方 |
| --- | --- |
| 「そこ詳しく」 | その区切りを**さらに細かく割って**辿り直す |
| 「戻って」 | 前の区切りへ。**地図を再掲して現在地を示す** |
| 「そこは飛ばして」 | 1 行の要約だけ残して次へ |
| 「なぜこうなってるの」 | **その場で答える。** 深掘りが要るなら `/break-down` へ渡す |

**寄り道から戻ったら、地図のどこにいるかを言い直す。** 離れると現在地が失われます。

### 6. 着いたら振り返る

**目的地に着いたことを明示する。** 辿り終えたかどうかは、読み手には分かりません。

- **通った経路を 3〜5 行で振り返る。** 区切りの見出しを並べるだけでよい
- **辿らなかった枝を 1 行。** 「エラー時はこちらへ抜けますが、今回は通っていません」
- **次に辿ると繋がる場所**を 1〜2 個。対になる処理、呼び出し元、テスト

## 出力の目安

| 単位 | 目安 |
| --- | --- |
| **地図** | 3〜8 行。図は枝分かれがあるときだけ |
| **1 区切り** | **抜粋 1 個 ＋ 説明 2〜5 行 ＋ 次への 1 行。** これで 1 回の応答 |
| **振り返り** | 5 行程度 |

**1 回の応答で 1 区切り。** これが既定です。区切りが極端に小さいときだけ 2 つ続けてよく、そのときも**止まるのは 1 回**。

## やってはいけないこと

- **コードを書き換えること。** 説明だけを行う。修正が要るなら指摘に留め、ユーザーの指示を待つ
- **一度に複数区切りを出すこと。** 一括で渡すなら `/explain-code`。**本スキルの存在理由が消える**
- **止まらずに進むこと。** 各区切りの末尾で必ず尋ねる
- **地の文で「次へ進みますか？」と書いて済ませること。** 読み飛ばされ、こちらは待ち続けることになる
- **起点と目的地を決めずに歩き出すこと。** 辿るうちに目的が曖昧になる
- **地図に内容を書き込むこと。** 地図は現在地のためのもので、そこで説明を始めると一括になる
- **区切りを分断すること。** 値を持ち回って繋ぐ。**連続性が本スキルの価値**
- **寄り道から戻ったときに現在地を言わないこと。** 離れると地図のどこにいるか失われる
- 実装手順（ステップ 1, 2, 3…）を勝手に添えること。聞かれたら出す

## 関連

- `/explain-code`（実装の説明）: **兄弟。** 説明する内容は近いが、**あちらは一度に渡す**。「全部いって」と言われたらあちらの形へ切り替える
- `/break-down`（噛み砕いて説明する）: **俯瞰が要るときの渡し先。** 辿る前に地図が欲しいなら先にあちら
- `plain_language_explanation.md`（噛み砕いた説明）: 文法をどこまで開くかはあちらが決める。言語ごとの習熟度は `CLAUDE.md`
- `decide_or_ask.md`（自分で決めるか尋ねるか）: **区切りで尋ねる形**（`AskUserQuestion`）はあちらが定める
- `report_formatting.md`（報告に貼る識別子の書式）: `file:line` で指す規定はあちらが持つ
- `verify_before_asserting.md`（断定の前に裏を取る）: 辿る前に実物を読む。**推測で経路を繋がない**
