`/create-pr` → `/loop-ai-reviews` を順に呼ぶ**ラッパー**です。判定基準も手順も持たず、順序だけを管理します。

| やること | 担当 |
| --- | --- |
| 点検・コミット・PR 作成 | `create-pr` |
| AI レビューの起動 → 完了待ち → 指摘対応を N 周 | `loop-ai-reviews` |
| 周回後の仕上げ（点検・PR 説明の更新） | **`loop-ai-reviews` が内部で `finalize-pr` を 1 回呼ぶ** |

**`finalize-pr` をこのスキルから呼びません。** `loop-ai-reviews` が担っており、重ねると点検 3 種が二重に走ります。指摘ゼロで終わった周は差分が動いていないので、そもそも仕上げが要りません（`create-pr` の時点で点検済み）。

## 進め方

### 1. 周回数の決定

引数の数値を使い、**省略時は 2** とする。上限 5 は `loop-ai-reviews` 側で丸められる。

**AI レビューは 1 周ごとに課金される。** 開始前に「PR を作成し、AI レビューを N 周回す」と 1 行伝える。

### 2. PR の作成

`create-pr` を Skill ツールで呼ぶ。ユーザーから渡された情報（ブランチ・base・Backlog 等）はそのまま引数に載せる。

**既に PR があるなら中断する。** `create-pr` は新規作成の責務で、既存 PR の更新は `update-pr-description` が担う。この場合は `loop-ai-reviews` だけを呼べばよい旨を伝えて終了する。

### 3. AI レビューの周回

`create-pr` の完了を待ってから、`loop-ai-reviews` を Skill ツールで呼び、Step 1 で決めた周回数を渡す。PR が無い状態ではレビューを起動できないので、順序を入れ替えない。

### 4. 完了報告

各スキルの報告を**そのまま二重に貼らない**。要点だけ拾って 1 つにまとめる。

- 作成した PR の URL（draft 状態・assignees・reviewers を 1 行で）
- 周ごとの結果（run ID / 指摘件数 / 対応したコミット）
- 打ち止めた理由

## 出力の目安

- 3〜6 行。PR の URL と、周回の結果を 1 行ずつ
- 途中で止まったときは、どのステップで何が起きたかを明記する

## やってはいけないこと

- **`finalize-pr` を呼ぶこと**。`loop-ai-reviews` が担う
- 各スキルの手順・判定基準をこの本文で再定義すること。**順序だけを管理する**
- `create-pr` の完了を待たずに `loop-ai-reviews` を呼ぶこと
- 周回数の省略時に 1 周で済ませること。**既定は 2**（1 周目の指摘に対応した差分を、もう 1 周見てもらうため）
- PR を ready 化すること（`no_auto_ready_pr.md`）

## 例外

- ユーザーが「レビューは要らない」と明示した場合は `create-pr` だけで終える
- 既に PR があり、ユーザーがレビュー周回だけを求めている場合は Step 2 を飛ばす
