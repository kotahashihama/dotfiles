## 6. 書けた指摘を敵対的に検証する

**ここで構えを切り替える。** Step 5までは「指摘が成立する根拠」を集めていた。ここからは**自分が書いた指摘を壊しにいく**。

**役割を変える。** 指摘を書いた本人ではなく、**独立した懐疑的なレビュアー**として読む。目的は改善提案ではなく**反証**。「この指摘は間違っているのでは」を前提に、成立していない箇所を探す。

**構えを変えないと、確認は追認になる。** 「合っているか」で読むと、合っている理由が見つかります。**「どこが間違っているか」で読んで初めて、成立しない箇所が出てくる**。

| | Step 5まで | Step 6 |
| --- | --- | --- |
| 構え | 指摘を**立てる** | 指摘を**壊す** |
| 問い | 「根拠はあるか」 | **「この根拠は成立しないのでは」** |
| 残すもの | 指摘 | **判定と根拠**（なぜ成立する / なぜ落とす） |

**敵対的なのは読み方であって、書き方ではありません。** 向ける先は**自分が書いた指摘**で、相手のコードでも相手本人でもない。

| | 敵対的に扱う | 扱わない |
| --- | --- | --- |
| 対象 | **自分が書いた指摘** | 相手のコード・PR 本文・相手本人 |
| 場面 | **Step 6（投稿前の検証）** | 投稿する文面 |

**投稿する文面はこの工程の影響を受けない。** 結論 → 根拠 → 代案の流れも、「〜はいかがでしょうか？」と判断を仰ぐ形も、そのまま（下記「コメント本文の書き方」）。

**壊しにいった痕跡を文面へ残さない。** 「反証を試みたが成立した」「疑わしいが残す」のような**過程は書かない**。残った指摘だけを、いつもどおりの温度で書く。

**1件でも的外れがあると、正しい残りの指摘まで疑われます。** レビューの価値は指摘の件数ではなく、**書いてあることが信用できるか**で決まる。落とすことを恐れない。

| 疑うこと | 潰し方 |
| --- | --- |
| **その規約は本当に存在するか** | 原文を開いて引用する。要約・記憶・「たしかそう書いてあった」で書かない |
| **その項目の定義を読んだか** | 書式・記入値への指摘は、**定義（テンプレート・スキーマ・列の説明）を開いてから**。定義は別ファイルにあることが多い |
| **「該当なし」は本当に該当なしか** | 検索が空を返しただけのことがある。**必ず当たる入力で検算してから**「使われていない」「前例がない」と書く |
| **規約どおりに書くと本当に動くか** | 推奨手段が実装の都合で機能しないことがある。**規約と実物が食い違うなら、実物が正しい** |
| **ガイドライン自身に公認例・例外がないか** | 同じドキュメントに「✅ OK」として載っている書き方を、違反と呼ばない |
| **既存コードは本当に違う流儀か** | **base 側で全件数え、数える単位と内訳を添える**（ `git show <base>:<path>` ）。2〜3本では足りず、**割れていれば指摘が立たない**（後述） |
| **PR 本文で既に説明されていないか** | 「後続 PR で対応」「意図的にこうした」と書かれている点を、知らずに指摘しない |
| **差分の別の場所で対応済みでないか** | 指摘対象のシンボルを差分全体で `grep` する |
| **この PR のスコープ内か** | 触っていない既存コードへの指摘は出さない。伝えたいならユーザーへの報告に回す |

**「規約に書いてあるから違反」で止まらない。** 規約が示す手段が、そのコードベースでは機能しないことがある（エラー型に判定メソッドが無く、規約推奨の比較方法が常に false になる、等）。**規約 → 実物の順で確かめ、食い違ったら指摘ではなく規約側の問題として扱う。**

**「2〜3本開く」では多数派が判定できない。** リポジトリテストのヘルパーへ渡す構造体の流儀を調べたとき、隣の1本を見た委譲先は「共有の型を使う流儀」と結論したが、**base の呼び出し49箇所を数えたら22対22で割れていた**。

**同じ「全件数えた内訳」が3通り出る。** 数える単位を決めないと数が定まらない。

| 数える単位 | 出た数 |
| --- | --- |
| 集計して上位だけ見る（ `head` で切る） | 22対15。**枠の外に4件落ちる** |
| `&` 以降の文字列 | 22対25。構造体でない渡し方が混ざる |
| **構造体リテラル `&Name{` だけ** | **22対22** |

**内訳と一緒に、数える単位も書く。** 受け取った側は手元で数え直すので、単位が違えば多数派が入れ替わる。

| 内訳 | 指摘 |
| --- | --- |
| **片方だけ** | **してよい**。既存の流儀がある |
| **偏りはあるが両方定着** | **しない**。22対15で「これが流儀」と言うと、**もう片方を書いた側に理由が立たない** |
| **割れている** | **しない**。合わせる先が決まらない |

**投稿するのは反証して残ったものだけ。** ただし**落とした候補は、落とした理由とセットでユーザーへ報告する**（Step 7）。「規約はあったが実装では機能しない」「既存を数えたら少数派だった」は、**次にユーザー自身がレビューするときの判断材料**になる。1件1行に収める。
