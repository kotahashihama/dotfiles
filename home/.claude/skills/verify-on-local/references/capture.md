# /verify-on-local の参照: 撮り方

本体の撮影の段から開く。PR への貼り方（並べ方・`--attach`・撮り直した後の貼り替え）は `/update-pr-description` の `references/testing.md` が持つ。

## 静止画

- **撮る手立ては環境ごとに違う。** `ls ~/.claude/scripts/` で撮影用のスクリプトがあるか見る。無ければユーザーへ頼む
  - **実画面が撮れないなら、代用せずに撮らないと報告する。** Storybook やモックで作った絵は、**レビュアーから実画面と区別が付かない**。証拠になっていないのに証拠に見えるほうが、無いより悪い
    - **「代用しない」だけでは足りない。** 次の人は別の代用を探すので、**撮れないときは貼らずに報告する**まで決めておく
  - **撮る前に、配信しているものと API の疎通を確かめる。** どちらかが落ちていると、操作が効かない形で失敗するので、**自動化の側の不具合に見える**（実際に、API が停止しているのを「クリックが送信にならない」と読み違えた）
- **どこを直したかが1枚で分かる位置を撮る。** 全画面だと検索フォームやヘッダで埋まり、**直した箇所が画面外に出る**。目印の語までスクロールしてから撮る
  - **表のセルへ入れるなら特に。** 列幅に押し込まれるので、2列なら各画像が半分の幅になる
- **操作した直後に撮らない。** 通信が止まっても**再描画・画像の読み込み・アニメーションは終わっていない**ので、待たずに撮ると崩れた絵になる
  - **待つ対象は、画面に出るものにする。** 通信を待つ形（URL で絞る）は**条件を外すと落ちる**うえ、外したことが「操作が失敗した」ように見える。**見せたい要素そのもの**（スナックバー・ダイアログ）を待てば外れない
- **検算は「2回撮って同じか」。** 同じ画面を2回撮ってバイト単位で一致すれば、安定して撮れている。**目視では判定できない**
- **一致は「描画が安定している」までしか示さない。** **撮る対象を間違えていても2回一致する**ので、URL かページ内の識別子（アカウント名・ID）を1つ照合する
- **貼る前に「2枚の差は、この PR をマージしたから出たものか」を問う。** 差が出る理由が他にあるなら、その2枚は成果を示していない
  - **Playwright やブラウザのバージョンを上げる PR では、変更前も変更後と同じバージョンで撮る。** 撮影のスクリプトが作業ツリーの Playwright を読むと、変更前後で Chromium が変わる。文字の描き方の差だけで画面全体に差が出る（実測: 1.53.2 と 1.63.0 で3万〜10万画素、同じバージョンで撮り直すと0画素）
  - **差が変えた箇所の周りではなく画面全体に薄く出たら、まず撮る側のバージョンを疑う**

  | 確かめること | 落ちる形 |
  | --- | --- |
  | **2枚が同じ対象か** | **別の対象を並べ、差が対象の違いから出ている** |
  | 2枚が base と PR のブランチで撮られているか | 片方を別のブランチで撮り、差が別の変更から出ている |
  | その差がこの PR の変更だけで説明できるか | データや設定の違いでも説明できてしまう |

  - **1枚ずつの識別子の照合では足りない。** 上の行は「1枚につき識別子を1つ照合する」で、ここは「**2枚で同じ識別子か**」。前者を済ませた人が後者も済んだと読みやすいので、**同じ値であることまで確かめる**
  - **2枚だけに出ている差も見る。** 片方にしか無い警告やラベルは、**対象が違う合図**であることが多い
  - **実際に取り違えた。** 前後で別の対象を撮っており、2枚の差は修正ではなく対象の違いから出ていた。**どちらも本物の画面なので、目視では気づけない**
- **基本は修正前も撮る。** 差が絵で分かるので、1枚だけより伝わる
  - **作り方はブランチの切り替え。** 実装を手で戻す必要はない。ローカルへ配信しているものを base のコミットへ切り替え、同じ操作をして撮り、PR のブランチへ戻す

    ```bash
    git checkout --detach origin/<base>   # 修正前を撮る
    git checkout --detach origin/<PR のブランチ>  # 修正後を撮る
    ```

  - **作業ツリーを共有しているなら先に一声かける**（ `notify_related_repo_sessions.md` ）。切り替えは相手の足元を変える
  - **副作用のある操作では、3つの時点で状態を見る。** 押すと変わるので、2回目は同じ画面にならない

    | 時点 | 見る理由 |
    | --- | --- |
    | **始める前** | 前の実行の結果が残っていると、**押すボタン自体が別のものに変わっている** |
    | **押す前** | 戻す手順を用意しておく。用意せずに押すと撮り直せない |
    | **落ちた後** | **スクリプトが落ちても操作は成功している**ことがある。確かめずに再実行すると、同じ操作を何度も通す |

    実際に、撮影の手前で落ちるスクリプトを3回動かし、**毎回追加が成功していた**。落ちた場所しか見ておらず、データを見るまで気づかなかった
  - **難しければ修正後だけでよい。** 修正前の状態を作れない（データが無い・環境が揃わない）ときは、無理に作らず1枚にする

## 動画

- **録画の範囲は context の生存期間で決まる。** `recordVideo` は context のオプションなので、**`newContext` から `close()` までの全部が入る**
  - **ログインは別の context でやる。** 管理者ログインと強制ログインを録画すると、**管理者のメールアドレスと顧客企業名が公開される**
  - **`storageState` で cookie だけを持ち回る**（実測: 1つ目で立てた cookie が2つ目で見え、録画は2つ目だけに掛かる）
  - **サーバー側のセッションだと持ち回れない。** その場合はこの経路では撮れないので、**撮らずに報告する**
- **`page.video().path()` は閉じた後でないと使えない。** 参照は**閉じる前**に取り、パスは**閉じた後**に読む。順序が入れ子になる
- **照合が「持ち回れたか」の検査を兼ねる。** 静止画と同じ照合（URL とページ内の識別子）が落ちたら、**別のアカウントの画面か、ログイン画面へ飛ばされている**
  - **落ちたら動画を消す**（ `video.delete()` ）。**見せたくない画面が入っている可能性があるものを残さない**
- **検算は静止画側で行う。** **動画は2回撮ってもハッシュが一致しない**（実測: 同じ操作でサイズは6,818バイトで同じ、ハッシュは別）。描画の安定と対象の照合は静止画で確かめる
- **ナレーションを付けるなら macOS 内蔵の `say` を使う。** キーも課金も要らない（ `say -v Kyoko -o out.aiff` ）。日本語の声は9種
  - **映像は再エンコードしない。** `ffmpeg -c:v copy -c:a libopus -shortest` で音声だけ足せば `.webm` のまま出る
  - **音声トラックが入ったかを見る。** `ffprobe -select_streams a` が空なら失敗している。**成功表示だけでは分からない**
  - **中間ファイルを消して、消えたことを確かめる。** 切る手と消す手は別のコマンドなので、`rm` の成功表示ではなく**存在しないこと**を見る
