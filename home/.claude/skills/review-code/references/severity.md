# 重要度の判定と裏取り

`must` / `imo` / `nits` の3段階を決めるための規定。**単発レビューと並列レビューの両方がこれに従う。**

## 判定表

| 指摘の種類 | 重要度 |
| --- | --- |
| 動作不良を起こすバグ（**具体的な失敗シナリオを提示できるもの**） | **must** |
| セキュリティ（認証・認可の漏れ、インジェクション、機微情報の露出） | **must** |
| **宣言された境界・依存方向への違反** | **must** |
| 対応するテストの**欠如・未更新**（免除対象を除く） | **must** |
| **繰り返し処理の中での重い呼び出し**（N+1・O(n^2) 等） | must（**データ規模が読めなければ imo**） |
| スキーマ・列挙値の**非互換**（既存データ・併走コードが壊れるシナリオを提示できる） | **must** |
| 複雑度（長大な関数・深いネスト・責務過多・重複・過剰抽象化） | **imo**（保守不能レベルのみ must） |
| 既存テストの網羅不足（新規分岐・境界値・エラーパス） | imo |
| エラー処理の書式・命名規約の逸脱 | imo |
| 命名と実際の振る舞いの乖離・不自然な初期値 | imo（**実バグに至っているなら must**） |
| コメントが外側の関心事に言及・コメントと実装の乖離 | imo |
| 既存実装とのパターン不一致・既存ヘルパーの再発明 | imo |
| 代替アプローチの提案、意図を確認したい箇所 | imo |
| 変数名の情報量不足・コードをなぞるだけのコメント | nits（**読み違いを誘発するなら imo**） |
| typo・デバッグコードの残骸・軽微なフォーマット崩れ | nits |

**免除対象**は、そのリポジトリの規約が定めるもの（生成物・型定義のみのファイル・DI の配線など）。規約が定めていなければ、テスト欠如は指摘対象です。

## must は1件ずつ裏を取る

**根拠を書けないなら imo 以下へ下げる。** 満たすべきは次のどちらか一方だけです。

| 根拠の型 | 確かめ方 |
| --- | --- |
| **規約違反** | 根拠に挙げた**規約ファイルを Read し、該当記述が実在して指摘内容と一致すること**を確認する。引用が曖昧・確認できないなら `imo` へ降格 |
| **失敗シナリオ** | 検出箇所のコードを Read し、**「この入力・状態」から「壊れる行」までを実コード上で追えること**を確認する。途中の分岐で防がれている・経路が追えないなら `imo` へ降格 |

**上げるときは、下げるとき以上に裏を取る。** 下げすぎても誰の時間も奪いませんが、**上げすぎるとマージを止めます**。

## 迷ったら1段下げる

- **100%の確信が無ければ1段階下げる。** 誤検知より見逃しを許容します
- **意図が読み取れないときは推測で must を付けない。** `imo` で「〜の意図か確認したい」と出す
- **代替案の無い命名指摘は採用しない**

## 件数を増やさない

| 規律 | 中身 |
| --- | --- |
| **同種は1件に集約** | 同じ規約違反・同じパターンが複数箇所にあるなら、代表1件にまとめて該当箇所を `path:line` で列挙する |
| **好みレベルは出さない** | 修正しなくても支障が無いものは落とす |
| **判定の問い** | 「**読んだ人がこの指摘で行動を変えるか**」。変えないなら出さない |
| **15件を超えたら** | **削るのではなく集約をやり直す**。同種がまとまっていないサイン |

**指摘ゼロで問題ありません。**

## 他の体系から受け取った重要度は読み替える

**同じ語でも定義が違います。** 委譲先スキルの `must` と、投稿先リポジトリの `[must]` （かならず変更して）は別の基準です。

**受け取った判定をそのまま通さず、この表を当て直す。** 語が一致しているときほど、素通りしやすい。
