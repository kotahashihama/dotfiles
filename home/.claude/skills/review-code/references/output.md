# 出力フォーマット

## 並べ替え（機械的に適用する）

1. セクション順: `must` → `imo` → `nits`
2. 各セクション内は**ディレクトリの近い順**（同じ領域の指摘が並ぶ）
3. 同一ディレクトリ内はファイルパスの辞書順

## 形

**一行要約を見出しにする。** 検出箇所・根拠・修正案は、その配下へネストします。ファイルパスを要約と同じ行に置かないのは、**狭いターミナルで折り返して読めなくなる**ためです。

**指摘1件ごとに severity ラベルを付けない。** セクション見出しが表しているので二重になります。

```markdown
# コードレビュー結果

## 対象範囲

- diff 範囲: [範囲]
- 変更ファイル: [対象件数] 件（除外: [除外件数] 件）
- 読んだ規約: [Read した規約ファイルのパス。無ければ「見つからず」]

## サマリ

- must: [件数] / imo: [件数] / nits: [件数]
- 全体所見: [1〜2行。問題なければ「境界・依存方向に問題なし」]

## must（マージブロッカー）

### [一行要約]

- **観点**: [下記の観点名から1つ]
- **検出箇所**:
  - `path:line`
  - （集約した指摘は該当箇所をすべて列挙）
- **根拠**: [失敗シナリオ、または規約ファイル名と該当記述]
- **修正案**: [修正後の形が想像できる具体度で]

（無ければ「なし」）

## imo（改善提案）

（must と同形式。無ければ「なし」）

## nits（些細な指摘）

### [一行要約]

- **観点**: [観点名]
- **検出箇所**:
  - `path:line`
- 修正内容を1〜2行で

（無ければ「なし」）

## 対応チェックリスト

- [ ] `path` — [一行アクション]（must）
- [ ] `path` — [一行アクション]（imo）
- [ ] nits 一括対応 — [typo 修正・残骸削除などの列挙]
```

## 観点名

**アルファベットや番号で書かない。** 読み手が対応表を引くことになります。

| 観点名 | 何を指すか |
| --- | --- |
| **正確性** | この入力・状態で壊れる |
| **セキュリティ** | 認証・認可・入力値・機微情報 |
| **境界の違反** | 宣言された依存方向・責務分担への逆らい |
| **複雑度** | 長大・深いネスト・責務過多・重複・過剰抽象化 |
| **規約違反** | そのリポジトリの規約ドキュメントに反する |
| **テストの追随** | 欠如・未更新・網羅不足 |
| **命名** | 名前と振る舞いの乖離 |
| **コメント** | 外側の関心事への言及・実装との乖離 |
| **配線漏れ** | 登録・結線が入口まで通っていない |
| **境界の契約不一致** | 呼び出し側と実装側で引数・nil・エラーの扱いがずれている |
| **エラーの伝播** | 握り潰し・nil の未考慮 |
| **データ整合性** | トランザクション境界・部分更新・順序依存・競合 |
| **性能** | 繰り返しの中の重い呼び出し・不要な再計算・再描画 |
| **互換性** | スキーマ・列挙値・公開契約の非互換 |
| **仕様書との整合** | 実装と仕様書のずれ |

**表に無い観点を足してよい。** その差分固有の危うさがあるなら、そちらを優先します。

## 対応チェックリスト

**修正作業の推奨順に並べる。** must → imo の順で、**同一ファイルへの対応は連続させる**（ファイルを開き直す回数が減る）。nits は末尾に1項目へ集約します。
