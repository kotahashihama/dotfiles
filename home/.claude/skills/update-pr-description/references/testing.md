# /update-pr-description の参照: testing

本体の手順3から切り出した詳細。本体の該当する項目から開く。

## 動作確認をしていない旨を書かない

- **動作確認をしていない旨を書かない**。テスト内容の節には**自分が実行した検証だけ**を書く
  - **画面が変わる PR では、スクリーンショットを撮って貼る。ただし `--screenshot` が渡されたときだけ**
    - **既定で撮らないのは、実環境へログインするから。** 撮影の経路が他人のアカウントへ入る操作を含むなら、**監査ログに残って取り消せない**（ `decide_or_ask.md` ）。重さは理由にならない（マシンが速くなれば消える）
    - **`--no-screenshot` は作らない。** 既定が撮らないので打つ理由が無い。既定が変わったときに足す
    - **撮り方は `/verify-on-local` の `references/capture.md` が持つ**（撮る手立て・描画を待つ・2回撮って照合する・修正前の作り方・副作用のある操作）。ここが持つのは、貼るかどうかと貼り方だけ
    - **この規定は `/create-pr` と `/ship-pr` にも効く。** あちらは本ファイルを正本として参照しているので、`--screenshot` と `--video` を受けたら同じ判断で動く
    - **画像が2枚以上なら、左右に並べる。** 縦に積むと、**読み手が往復して差を探すことになる**

      | 手元にあるもの | 並べ方 |
      | --- | --- |
      | **2枚**（修正前と修正後） | **1行2列。見出しは「修正前」「修正後」** |
      | **2枚以上**（操作ごとの修正後など） | **1行 N 列。見出しは比べる軸（操作名・状態名）** |
      | **1枚**（修正前を用意できないとき） | **行を数値にして、画像は最後の行へ1枚**。修正前は表の記述が持つ |

      - **「列に並べる」と書かない。** 縦にも横にも読めるので、**行と列の数で言う**。実際に「表の列にして並べる」を縦（1列2行）と読んで、2件続けて積み上げた
      - **画像はすべて同じ行に置く。** 比べる軸を見出しの行（1行目）へ、観点（画面・DB の値・件数）を左端の列へ置くと、自然にそうなる
      - **数字が主役なら、そう見える形にする。** 実際に、件数だけが違う2枚を単独で並べて「**絵として差が出ていない**」と指摘を受けた。**数字を行に、画像を最後の行へ**置くと役割が立つ
      - **表のセルへ入れるなら、セルに `![alt](./x.png)` を書いて `--attach` する**（下記。バージョンによっては末尾へ追記されるので、貼った後に本文を読み直す）
    - **撮り直したら、貼り替えるまでを1つの作業にする。** 撮る手と貼る手は別のタイミングで動くので、**撮って満足して次へ進むと古い画像が残る**（実際に、描画待ちを入れて撮り直したのに貼り替えを忘れた）
    - **撮り足したら、まだ読まれていない撮り比べのコメントへ合算する。** 「前の撮り比べで見ていなかった…」の形で別のコメントを足さない（ `keep_records_current.md` の「まだ誰も読んでいない投稿は、書き換える」。読まれたかの見分け方もあちら）
      - **添付は PATCH では上げられない。** 合算した全文を `gh pr comment --attach` で新しく出し、古いコメントを消す。本文のリンクも新しい ID へ差し替える
      - 実際に、撮り足した分を別のコメントで出し、「まだ誰もレビューしていないのだから合算して」と言われた（4本の PR で計3件）
      - `gh pr comment --edit-last --attach` で書き換えと添付を同時にできるかは未検証
  - **操作の流れが変わる PR では、動画を撮って貼る。ただし `--video` が渡されたときだけ**
    - **静止画と使い分ける。** 見え方が変わったなら静止画、**遷移・順序・アニメーションが変わったなら動画**
    - **既定で撮らない理由は静止画と同じ。** 実環境へログインするので、監査ログに残って取り消せない
    - **`.webm` はそのまま貼れる。** GitHub が受け付ける動画は `.mp4` / `.mov` / `.webm` で、Playwright は `.webm` を出す。**変換は要らない**
    - **上限は画像と別枠。** 動画は**無料プランで10MB、有料で100MB**。実測では1440x900の8秒で約100KB
    - **動画は代替テキストを持てない**（プレイヤーとして描画される）。**何を見せているかは本文の側に書く**
      - **`--attach` に `#alt` を付けると止まる**（gh 2.101.0 で `cannot set alt text on video` ）。動画は `--attach ./x.mp4` とパスだけ渡す
      - **本文には `![](./x.mp4)` を単独の行で書く。** その行が添付の URL 単体に差し替わり、GitHub がプレイヤーとして描画する（ `body_html` に `<video>` が出ることで確かめる）
    - **録画の仕方は `/verify-on-local` の `references/capture.md` の「動画」が持つ**（ログインを録画しない・照合・ナレーション）
  - **画像や動画を受け取ったら本文へ貼る**。画像と GIF は10MBまで
    - **本文に `![alt](./x.png)` を書き、`gh pr edit --body-file <本文> --attach './x.png#alt'` を1回で渡す。** 相対パスは `gh` を実行するディレクトリから解決される
      - **gh 2.101.0 では、その位置で `user-attachments` の URL へ差し替わった**（表のセルの中でも。末尾への追記は起きなかった）
      - **それより前のバージョンでは、差し替わらずに末尾へ追記された実測がある**（バージョンは控えていない）。そうなると、壊れた参照と正しい画像が二重に残る
      - **貼った後に本文を取り直し、`./` の参照が0件で、画像が置きたい位置にあることを見る**。成功表示は差し替わったかを示さない
    - **添付を消す形の更新は書式のフックが止める。** 今の本文にある `![alt](URL)` が新しい本文に文字列のまま無ければ止まる。位置を動かすだけなら止まらないが、**代替テキストを変えると止まる**ので、**位置と代替テキストを決めてから1回で貼る**
      - **自分で貼ったものを意図して消すなら、コマンドの頭に `ALLOW_DROP_ATTACHMENTS='<URL> <URL>'` を付けて名指しする**（補足コメントへ移すとき等）。URL は丸ごと書く（完全一致で比べるので、一部だけでは通らない）。名指ししていない添付は止まるので、ユーザーが後から貼ったものは消えない
- 機密（ `.env` / credentials / 内部 URL）を含まないことを念のため確認
