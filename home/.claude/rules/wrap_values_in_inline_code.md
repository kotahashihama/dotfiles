# データ値と識別子はインラインコードで囲む

文章の中に**そのシステムに存在する値や名前**を書くときは、バッククォートで囲んでください。
会話・PR 説明・レビューコメント・課題管理ツールのコメント・ドキュメント、**こちらが書くものすべて**が対象です。
これは全プロジェクト共通の規約です。

## 判定は「読み手がそのまま打つか、貼るか」

| 囲む | 囲まない |
| --- | --- |
| 値・ID・変数名・テーブル名・列名・パス・コマンド（ `12` `user_id` `/settings` `task test` ） | 数量・件数（3ファイル / 21秒）。単位と詰める |
| **API が受け取る値**（ `owner` ） | **画面のラベル**（「オーナー」は鉤括弧） |

**同じ語でも、値か表示かで変わります。** API へ送る `owner` は囲み、画面に出ている「オーナー」は鉤括弧で示す。

**人名も、DB の行や画面の値として指すなら囲む。** 人そのものへの言及（「山田さんに聞く」）は囲まない。

## GitHub では、自動で解釈される記法だけ囲まない

**囲むとリンクになりません。** `POST /markdown` （ `mode: gfm` ）で5種とも実測した。

| 記法 | 裸 | 囲む |
| --- | --- | --- |
| `@ユーザー名` | メンションになる | **ならない。通知が飛ばない** |
| `#123` / `owner/repo#123` | 参照になる | ならない |
| 生の URL | リンクになる | ならない |
| **コミット SHA（40桁）** | **コミットへのリンクになる** | ならない |

**会話への報告では逆に囲む**（ `report_formatting.md` ）。クリックできないので、値として示すほうが役に立つ。

## なぜ

- 値と地の文の境界が無いと、**どこまでが値か読み手が決められない**。囲まない数字は助数詞にも年号にも見える
- 等幅で表示されるので、`l` と `1`、`0` と `O` の取り違えが減る
- 読み手はその値を**そのまま貼る**。囲めばコピーの単位が揃う

## 例外

- 引用・ログの原文（原文を書き換えない）
- ユーザーが書式を指定した場合

## 関連

- `no_space_between_number_and_unit.md` （数値と単位の空白）: **囲んだ後の前後の空白はあちら**（ `### インラインコードの前後は空ける` ）。本ルールは囲むかどうかを決める
- `github_cross_repo_reference.md` （他リポジトリの PR / issue）: **囲まない側の代表**。あちらが前提として置く「パス・コマンド・識別子は囲むのが正しい」の本体が本ルール
- `report_formatting.md` （報告に貼る識別子の書式）: **会話と GitHub で扱いが逆になる**。あちらは会話への報告が対象
