# GitHub で他リポジトリの PR / issue を参照するときは owner を省略しない

GitHub へ書く文章（PR 説明・コメント・レビュー返信）で他リポジトリの PR / issue に触れるときは、**`owner/repo#123` の形**で書いてください。
これは全プロジェクト共通の規約です。

## 期待する書式

| 参照先 | 書き方 |
| --- | --- |
| 他リポジトリ | `owner/other-repo#2950` |
| 同一リポジトリ | `#392` |
| コメントへのアンカー付き | `[このコメント](https://github.com/owner/repo/pull/123#issuecomment-...)` |

GitHub が自動でリンクにし、タイトルと open/closed も表示されます。生 URL より短く、リポジトリ名が変わっても腐りません。

## 禁止する書き方

- **owner を省略すること**。`other-repo#2950` も `#2950` も、**同一リポジトリの2950番**として解釈されます。番号が存在しなければリンクにならず、存在すれば無関係な PR に飛びます
- **同じ文書の2回目以降を省略すること**。「一度フルで書いたから以降は短くてよい」は成立しません。読み手はどの段落から読み始めるか分からず、リンクは1箇所ずつ独立に解決されます
- **バッククォートで囲むこと**。`` `owner/repo#123` `` はコード片として描画され、**GitHub が参照として解釈しません**。タイトルも open / closed も出ないので、読み手は番号を手で開くことになります

## なぜ

- 番号だけの参照は**リポジトリを跨いだ瞬間に意味が変わる**。書き手には自明でも、読み手には判別できない
- リンクが機能しないと、レビュアーは依存先を自分で探すことになる。**依存関係を示すために書いた参照が、かえって手間を増やす**
- **囲むべきものと囲んではいけないものが混在する。** パス・コマンド・識別子は囲むのが正しいので、同じ癖で参照まで囲むとリンクが消える。**種類ごとに判定する**

## 確認のしかた

書き終えたら、**本文中のすべての `#数字` を拾って、同一リポジトリのものか確かめる**。1箇所ずつ見ないと、前半だけ正しく後半で崩れている状態を見逃します。**owner の有無だけを見る検査では足りません**（囲まれていても当たる）。囲まれた側を別に数えて0件にする。

## 関連

- `github_note_generated_by_claude.md` （生成者表示）: どちらも GitHub へ書く文章の書式を定める
- `github_one_sentence_per_line.md` （1文ごとに改行し行末の句点を落とす）: 同上
- `report_formatting.md` （報告に貼る識別子の書式）: あちらはユーザーへの報告、本ルールは GitHub 上の文章が対象。**バッククォートの扱いが逆になる**。会話では囲んでコードとして示し、GitHub では囲むと自動リンクが消える
- `/create-pr` / `/update-pr-description` / `/review-pr` / `/resolve-ai-reviews` / `/resolve-human-reviews`: 本ルールが土台。**他リポジトリの PR を挙げる場面はどのスキルでも出る**
