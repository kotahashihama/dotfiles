# PR 説明・コミットにエージェント連携の話を書かない

PR 説明や commit メッセージには、**エージェント間の作業調整プロセス**を書かないでください。
これは Claude Code 側の運用都合であって、成果物（PR・コミット）には含めません。レビュアーが確かめられない手元の環境の事情も、同じく書きません（下記）。
これは全プロジェクト共通の規約です。

## 禁止する記述

- 「FE と連携」「BE と連携」等の、担当エージェント間で調整している旨
- 「他のエージェントと合意済み」「〇〇さんと相談済み」等の、合意プロセスへの言及
- 「対応 PR は別リポ #XXX で待機中」「先方の PR を ready→merge する順序調整」等の、他リポ／他エージェントの対応状況・マージ順の調整メモ
- セッション間通信 / サブエージェントといった仕組みそのものへの言及

## 期待する記述

- PR 説明に書くべきは「コードベース／プロダクトの状態、つまり何が変わるか」だけに絞る
- 破壊的変更である事実、feature flag OFF で未露出という安全性など、**成果物の性質**は残す
- 破壊的変更の追随が必要なことは、主体を伏せて事実だけ書く（例: 「 `label` を参照する箇所の追随が必要」）
- マージ順・リリース調整が本当に必要な場合も、フラグ状態など客観的事実として書き、「誰と／どのエージェントと調整したか」は書かない

## レビュアーが確かめられない手元の事情も書かない

**PR に書くのは、レビュアーが自分の環境で確かめられることだけです。** 手元の環境にしか無いものは、読んでも確かめようがありません。

| 書かない | 書く |
| --- | --- |
| 手元のホスト・ポート・パス（ `127.0.0.1:3307` や `/Users/...` ） | 何が要るか（「DB への接続が要るテスト」） |
| 非公開の検証用リポジトリで確かめたこと | 誰でも流せる手順と、その結果 |
| 個人の設定やツールの有無 | リポジトリに入っている設定とコマンド |

**判定は「レビュアーが同じことを自分の手で確かめられるか」。** 手元で流したテストの結果は、同じコマンドで再現できるので書いてよい。

実際に、PR の補足へ手元のテスト用 DB のポートを、テスト内容へ非公開の検証用リポジトリで確かめたことを書き、指摘を受けました。

## なぜ

- レビュアーが見たいのは「何が変わるか」であって「誰と合意したか・別リポの対応がどう待機しているか」ではない
- エージェント間調整はレビュアーにとってノイズであり、成果物の恒久的な記録としても不適切
- 合意相手や別リポの PR 番号は時間とともに陳腐化し、PR 説明の情報価値を下げる

## 例外

- ユーザーが明示的に「この連携内容を PR に書いて」と指示した場合のみ。
- それ以外は本ルールが常に優先する。

## 関連

- `no_instruction_echo_in_output.md` （成果物に指示を書かない）: **同じ形で、対象が違う**。本ルールはセッション間の調整、あちらはユーザーから受けた指示
- `notify_related_repo_sessions.md` （担当セッションへ連絡する）: **連絡はする、成果物には書かない**。あちらが前者、本ルールが後者
