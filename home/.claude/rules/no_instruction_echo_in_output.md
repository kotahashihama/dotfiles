# 成果物に、こちらが受けた指示を書かない

PR 説明・課題管理ツールのページ・ドキュメント・コード・コミットには、**ユーザーから受けた指示と、それを受けて範囲を決めた経緯**を書かないでください。指示は自分のメモに留め、成果物には**読み手が要る情報だけ**を置きます。
これは全プロジェクト共通の規約です。

**指示を覚えておくことと、指示を書き残すことは別です。** 前者は必要で、後者は読み手のためになりません。

## 判定は「読み手の判断が変わるか」

**「誰に言われたか」「なぜそう決めたか」を消しても、書いてある内容が成立するか。** 成立するなら、その説明は要りません。

| 漏出（**書かない**） | 状態の記述（**書く**） |
| --- | --- |
| 「〜という指示のため〜としている」 | 「〜は未計測」 |
| 「〜とは目的が違うため、〜は設けない」 | 「〜は別 PR で出す」（マージ順が変わる） |
| 「〜でよいとのことなので省略した」 | 「〜は対象外」（読み手が探しに行かずに済む） |
| 「スコープ外と判断したため触れない」 | 「〜は既存の挙動のまま」（影響範囲） |

**右の列も「やらないこと」を書いています。** 違いは、**読み手の次の行動が変わるか**だけです。左は変わりません——読み手が知りたいのは、そこに何が書いてあるかであって、なぜ書かれていないかではない。

## 最も混ざりやすいのは「やらなかったことの説明」

**範囲を絞る判断は、こちらにとっては大きな決定です。** 検討して、諮って、決めた。だから書き残したくなる。

ところが読み手から見ると、それは**存在しないものについての説明**です。読んでも得るものが無く、本題を探す手間だけが増えます。

**書式レベルの手がかりがあります。** 「〜のため」「〜ので」「〜とは違い」の**主語が、依頼・会話・別の課題**なら漏出です。

```
❌ A の計測とは目的が違うため、B のパターンは設けない
❌ 汎用的に使い回せるようにという指示で、共通名にしている
✅ B のパターンは計測していない
```

## 置き場

**捨てるのではなく、移す。** 経緯そのものに価値があることはあります。

| 中身 | 置き場 |
| --- | --- |
| 次のセッションが知っておくべき前提 | **自分のメモ**（auto memory） |
| その差分をなぜその形にしたか | **コミットメッセージ**の本文 |
| レビュー中だけ効く補足 | **PR の `[fyi]` コメント**（`write_invariant_why_in_code.md`） |
| 会話の中だけで足りるもの | **どこにも書かない** |

## 禁止する挙動

- **受けた指示を、そのまま成果物の文章にすること**
- **範囲を絞った理由を成果物に書くこと**。読み手には存在しないものの説明にしかならない
- 「〜という指示で」「〜と言われたので」「〜でよいとのことなので」を書くこと
- **他の課題・他の依頼との対比で、やらないことを説明すること**
- 経緯に価値があるからと、**置き場を選ばずに成果物へ書くこと**
- **型やスキーマで既に表現されている契約を、指示の言葉のまま文章で言い直すこと**（「必ず値が入る」「required として扱う」）

## なぜ

- 読み手は**成果物を読みに来ている**のであって、それがどう決まったかを追いに来ているわけではない。指示の説明は、探している情報の前に置かれた障害物になる
- **書き手には価値があるように見える。** 決めるのに手間がかかったぶん、その判断が重要に感じられる。読み手はその手間を知らないので、同じようには見えない
- 指示は**その場の文脈に依存**する。時間が経つと何の話か分からなくなり、消す判断もできないまま残る

## 例外

- ユーザーが「この経緯を残して」と明示した場合
- **その制約が読み手の行動を変える場合**（マージ順・前提条件・別 PR への分割）。これは指示の説明ではなく状態の記述にあたる

## 関連

- `no_review_comment_echo_in_code.md`（レビュアーの文言を転記しない）: **出どころが違う**。あちらはレビュアー、本ルールはユーザーの指示。どちらも成果物に持ち込まない
- `no_agent_coordination_in_pr.md`（連携の話を書かない）: 同じ形。あちらは**セッション間の調整**が対象
- `write_invariant_why_in_code.md`（不変の WHY だけ残す）: あちらは**賞味期限**で弾く。本ルールは**出どころ**で弾く
- `no_guesswork_in_records.md`（記録に推測を混ぜない）: どちらも**記録に何を書かないか**。あちらは**確かさ**、本ルールは**読み手に要るか**で判定する
- `concise_first_then_detail.md`（簡潔に）: あちらが挙げる「過程の説明」を、本ルールが**出どころの面から**具体化する
- `github_no_authorship_voice.md`（帰属を匂わせない）: あちらは**誰が決めたか**、本ルールは**なぜ決めたか**
