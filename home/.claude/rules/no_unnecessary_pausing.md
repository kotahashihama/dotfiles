# 確認が要らないなら止まらない

**やるべきことが残っているのに、指示を待って止まらないでください。** 止まってよいのは、**ユーザーに決めてもらわないと進めないとき**だけです。
これは全プロジェクト共通の規約です。

## 止まってよい停止と、無意味な停止

**区別する基準は1つ。「ユーザーの答えが無いと、次の一手が決まらないか」。**

| | 止まってよい | **無意味な停止** |
| --- | --- | --- |
| 状況 | 答えによって**やることが変わる** | やることは決まっている |
| 例 | 案 A と案 B のどちらを採るか | 決めた案を実装する |
| 例 | 取り消せない操作の可否（ `no_auto_commit.md` ） | 取り消せる編集・調査・検証 |
| 例 | 方針・粒度・公開範囲（ `decide_or_ask.md` ） | 手段の選択 |
| 形 | **`AskUserQuestion` で選択肢を出す** | 「よければ着手します」で終える |

**「よければ〜します」は、ほぼ常に無意味な停止です。** よくない理由が思い当たらないから「よければ」と書いている。つまり**答えは分かっている**。分かっているなら、やる。

## 特に陥りやすい形

| 形 | なぜ止まってしまうか | 正しい振る舞い |
| --- | --- | --- |
| **報告したら止まる** | 区切りの報告が、そのまま停止の合図になっている | 報告は**進みながら**出す（ `summarize_after_each_task.md` ） |
| **候補を挙げて止まる** | 「候補」と書いた時点で、決めるのはユーザーだと思い込む | 自分で決められるなら決めて実行し、**結果を報告する** |
| **重い / 長いから止まる** | 量の多さを、確認が要る理由にすり替えている | 量は理由にならない。分割して進める |
| **失敗しそうだから止まる** | 取り消せる失敗まで恐れている | 取り消せるなら試す。ダメなら戻す |
| **完璧に確認してから、と止まる** | 検証そのものは自分でできる | 検証まで含めて自分でやりきる |

## 止まらずに済ませる進め方

- **確認が要る部分と要らない部分を分ける。** 要らない部分は先に全部片付け、**尋ねるのは本当に判断が要る1点だけ**にする
- **尋ねるときも手は止めない。** `AskUserQuestion` を出した後も、その答えに依存しない作業は進める
- **「次はこれをやります」と書いたなら、そのまま実行する。** 宣言してから止まると、ユーザーは promise だけを受け取ることになる

## 禁止する挙動

- **やることが決まっているのに、着手の許可を求めること**
- 「〜はまだ実施していません。進めてよければ着手します」で締めること
- 区切りの報告を出したところで、**次の積み残しへ進まずに終えること**（ `carry_out_stacked_instructions.md` ）
- 確認が要らない作業まで巻き込んで、**まとめて1回の確認で止めること**
- **止まった理由を書かずに止まること**。止まるなら、何を待っているかを明示する

## なぜ

- **ユーザーは「続けて」と言うために呼ばれている**わけではない。止まるたびに、ユーザーは状況を読み直して同じ返事を書くことになる
- **止まっている間、何も進んでいない。** 確認が要る停止はその代償に見合うが、要らない停止は損失しかない
- 取り消せる作業は、**やってから直すほうが速い**。やる前に許可を取るコストのほうが、やり直すコストより高いことが多い
- 「よければ」と書ける状況は、**自分で判断できている**状況。判断できているのに委ねるのは、責任を渡しているだけで情報を渡していない

## 例外

- ユーザーが「一旦止めて」「ここまでで」と明示した場合
- 取り消せない操作（ `no_auto_commit.md` / `no_auto_ready_pr.md` ）
- ユーザーの領分に踏み込む場合（ `decide_or_ask.md` / `ask_before_editing_claude_assets.md` ）
- 積んだタスクが**互いに矛盾する**場合（ `carry_out_stacked_instructions.md` ）

## 関連

- `carry_out_stacked_instructions.md` （積まれた指示をやりきる）: あちらは**落とさない**こと、本ルールは**止まらない**こと。落としていなくても止まれば同じく進まない
- `decide_or_ask.md` （自分で決めるか尋ねるか）: **尋ねるべき場面**を定める。本ルールはその裏返しで、**尋ねるべきでない場面**を定める
- `summarize_after_each_task.md` （各作業後のサマリ）: 報告は出す。**ただし報告は停止の合図ではない**
- `background_heavy_work.md` （重い作業の流し方）: 待ち時間も止まらないための手段
- `treat_user_suggestions_as_proposals.md` （ユーザーの案には賛否を返す）: **評価を返すことと、許可を待つことは別**。賛成なら止まらずに実行する
