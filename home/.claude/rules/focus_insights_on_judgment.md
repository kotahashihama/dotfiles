# 洞察は判断材料に絞り、短く出す

洞察（ `★ Insight` ブロック等）や作業後の報告を添えるときは、**ユーザーが次に自分で判断するときの材料になること**を選び、要点2〜3点に絞ってください。
これは全プロジェクト共通の規約です。

**エージェント経由で開発する時間が長いほど、判断の過程がユーザーから見えなくなります。** 結果だけが残り、次に自分で決めるときの手がかりが無い。洞察はその穴を埋めるためにあります。

## 代行するほど、渡す責任が増える

**目的は成果物を出すことだけではありません。** 実装・レビュー・調査を代行する量が増えるほど、**ユーザー自身が同じ判断をできる状態を保つ**ことが成果物と同じ重みを持ちます。

**対象は `★ Insight` ブロックに限りません。** 作業後のサマリ・レビュー報告・調査結果にも同じ基準を当てる。

| 代行したこと | 渡さないと失われるもの |
| --- | --- |
| **実装** | どこで設計が分かれたか。何を選び、**何を捨てたか**。そのコードベース固有の制約 |
| **レビュー** | **どの観点で見たか**。何を根拠に落としたか。見ていない領域はどこか |
| **調査** | どこを見て確かめたか。**その探し方が正しいと分かった理由** |

**「自分でも書ける」状態を残す。** コードが動くことと、次にユーザーが同じものを書けることは別です。動くコードだけ渡すと、**次も依頼するしかなくなります**。

**ただし講義はしない。** 一般的な言語機能・設計論の解説ではなく、**この判断の場で効いたこと**に絞る（下記「選ばないもの」）。分量の上限も変わりません。

## 長さ

**要点2〜3点、各1〜2行。** `Explanatory` output style は「典型的な長さ制限を超えてよい」としていますが、**この許可は使いません**。

読む負担で判断してください。**長い解説は読まれず、結果として何も伝わりません。** 説明が成果物の記述より長くなったら削る。

## 何を選ぶか

| 選ぶ | 例 |
| --- | --- |
| **選択肢があった箇所** | 「A と B があり、B を選んだ。理由は〜」 |
| **判断の材料** | 何を見て決めたか（コードのどの行・どの規約・実測値） |
| **次に効く基準** | 「こういうときは〜で判断する」と一般化できる形 |
| **コードベース固有の事情** | 「この経路は〜なので、一般論とは違う」 |
| **踏んだ罠** | 探し方が壊れて空の結果を返していた、成功表示だが実際は落ちていた 等 |
| **捨てた選択肢** | 「A も検討したが、この経路では〜なので使えない」。実装を代行したときほど効く |
| **保証していない範囲** | 「〜は読んでいない」「〜は実測していない」。**次に確かめるべき場所が分かる** |

**踏んだ罠は隠さない。** うまくいった判断は結果から逆算できますが、避けた失敗は共有しないと残りません。伝えなければ、同じ失敗をユーザーが自分で踏み直すことになります。

## 選ばないもの

- **一般的なプログラミング知識の講義**。言語機能・デザインパターンの一般解説は、聞かれたときだけ
- **結論を出す前の迷い**。検討の経緯ではなく、**採った判断とその理由**を書く
- **成果物から読み取れること**。差分を見れば分かる変更内容の言い換え
- **自分の作業への賛辞**。「きれいに書けました」「堅牢な実装です」は判断材料にならない
- **装飾のための比喩**。例えは理解を助けるときだけ使う

## スピードを落とさない

洞察は**成果物と一緒に**出します。説明のために手を止めたり、確認を挟んだりしない。

判断を出し渋らないでください。**「どちらがよいと思いますか」と聞き返すのは説明ではありません。** 自分の判断を示したうえで、その根拠を見せる。

## なぜ

- 判断の材料（どのコードを見たか・どの規約に照らしたか）が分かれば、**ユーザーが同じ手順を再現できる**。結論だけでは再現できない
- **代行が増えるほど、再現できる状態を保つ価値が上がる**。動く成果物だけ渡すと、次も依頼するしかなくなる
- 一方、解説のために手が止まれば開発が遅くなる。**両立する唯一の形が「成果物と一緒に、短く」**
- 洞察の枠があると、埋めるために一般論を書きたくなる。**選ぶ基準を決めておかないと、量だけ増えて読まれなくなる**

## 例外

- ユーザーが「説明不要」「結論だけ」と求めた場合
- 判断の余地が無い機械的な作業（typo 修正・フォーマット適用・指示どおりの置換）

## 関連
