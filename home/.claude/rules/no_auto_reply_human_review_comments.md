# 人間のレビューコメントへは勝手に返信しない

PR に付いた**人間のレビュアー**によるレビューコメントに対しては、こちらから勝手に返信を書き込まないでください。
これは全プロジェクト共通の規約です。

## 対象

- 人間のユーザーが投稿した PR レビューコメント（インライン・レビュー本文・PR コメント欄いずれも）
- 種別を問わず、`[must]` / `[imo]` / `[nits]` / `[ask]` / `[fyi]` 全てが対象

## 例外（自動返信してよいのはこの範囲のみ）

- **AI レビュワー**（`github-actions[bot]` 等の bot アカウント）からのレビューコメント。
  - `/resolve-ai-reviews` スキルで扱う対象がこれに該当する。
- ユーザーが明示的に「このコメントに〇〇と返信して」「返信しておいて」等と指示した場合。

## 期待する挙動

- 人間のレビューコメントに対しては、**コード修正のみをこちらで行い、返信は書かない**。
  - 修正した内容とコミットハッシュを**ユーザーに口頭で報告**するに留める。
- 返信するかどうか・返信文言はユーザーが判断する領分。エージェントが勝手に決めない。
- `/resolve-ai-reviews` や類似スキルを起動する際も、対象を **bot コメントに限定**し、人間コメントには手を出さない（対象コメント抽出時に `user.type == "Bot"` 等でフィルタする）。

## なぜ

- 人間のレビュアーへの返信は、書き方・熱量・タイミングを含めて**当事者間のコミュニケーション**であり、エージェントが代理で書くとニュアンスがズレる／礼を欠く／議論の流れを壊す等の事故が起きる。
- AI レビュワーへの返信は「コミットハッシュを返して閉じる」等の**機械的な運用**で完結するため、自動化して問題ない。この 2 つは扱いを明確に分ける。

## 起動経路による制限（デフォルト "返信しない"）

`/resolve-ai-reviews` スキル起動時のみ、GitHub 上での bot コメントへのコミットハッシュ／理由返信を許可する。

それ以外の経路（ユーザーが「このコメントに対応して」「レビューを直しといて」等と自然文で依頼した場合を含む）では、投稿元が bot / 人間のいずれであっても、GitHub 上でのレビュー返信は行わない:

- コード修正のみをコミット & プッシュする
- コミットハッシュはユーザーに口頭（会話）で報告する
- ユーザーが必要と判断すれば、自身で GitHub 上へ返信する

これにより「文脈からの誤認で bot 扱いして人間コメントに返信してしまう」事故を、bot 判定の機械化に加え起動経路の側面からも防ぐ。

## 返信要否をユーザーに確認しない

自然文経路でレビュー対応を依頼された場合、以下を守る:

- ユーザーに「返信しますか？」「レビュアーが人間か bot かで扱いが変わるので教えてください」等の**返信要否確認をしない**。
- 修正・push 完了は**口頭でハッシュ報告するのみ**にとどめ、返信の話題自体を持ち出さない。
- 返信が必要なら、ユーザーが「返信しておいて」「このコメントに〇〇と返して」等と明示指示を出す（これが「例外指示」節にあたる）。

理由: 「返信するかどうかはユーザーが判断する領分」であり、こちらから確認を投げること自体が判断領域への侵入。ユーザーは必要なら明示指示を出すので、こちらは受け身に徹する。

## 例外指示

- ユーザーが「このコメントには自分で〇〇と返しておいて」「返信もしておいて」等と明示した場合のみ返信を代行してよい。
- `/resolve-ai-reviews` を明示起動した場合は、そのスキルの仕様に従って bot コメントに返信する（本ルールの「起動経路による制限」が優先されるのは自然文経路のみ）。
- それ以外は本ルールが常に優先する。

## 関連

- `/resolve-human-reviews`（人間レビューへの対応スキル）: 本ルールが規定する「返信しない」を守ったうえで、**では何をするか**（修正の粒度・コミットの分け方・対応表の報告）を担う。人間コメントへの対応を依頼されたらこのスキルを使う
- `explain_review_comment_first.md`（対応可否をユーザーに尋ねる）: レビューコメントが共有されただけで対応指示が無い段階を規定する。対応指示が出た後は上記スキルへ移る
