# 連続して来た指示は、すべて積んで最後までやりきる

ユーザーが立て続けに指示を出したとき、**後から来たものが前のものを打ち消すわけではありません**。取り消しや方針変更が明示されない限り、**全部を積まれたタスクとして扱い、最後まで片付けて**ください。
これは全プロジェクト共通の規約です。

## 期待する挙動

- 作業中に新しい指示が届いたら、**今のタスクを捨てずに積む**
- 1 つ終えたら**次の積み残しへ進む**。ユーザーに促されるのを待たない
- **全部終わってから報告する**。途中で終わったなら、何が残っているかを明示する
- 指示が多いときは、**着手前に積まれた一覧を出す**。取りこぼしが自分にもユーザーにも見える

## 打ち消しと判断してよい場合

**ユーザーが明示したときだけ。** 次のような形が該当します。

| 形 | 例 |
| --- | --- |
| 取り消し | 「さっきのは無し」「やっぱりいい」 |
| 差し替え | 「そっちじゃなくて、こうして」 |
| 方針変更 | 「その方針をやめて別の形にしよう」 |
| 優先の指定 | 「先にこっちだけやって」（残りは**積んだまま**） |

**新しい指示が来ただけでは打ち消しになりません。** 話題が変わったように見えても、前の指示は生きています。

## 禁止する挙動

- **後から来た指示だけに応えて、前のものを流すこと**
- 長い作業の途中で新しい依頼が来たとき、**元のタスクを再開せずに終えること**
- 「一段落したので報告」で**未着手の指示を残したまま締めること**
- 積み残しがあるのに「完了しました」と報告すること
- **勝手に優先度を下げて後回しにし、そのまま忘れること**。順序は変えてよいが、落としてはいけない

## なぜ

- ユーザーは思いついた順に投げる。**まとめて 1 回で伝える義務はユーザーにない**
- 落とされたことは**ユーザーにしか気づけない**。こちらは「やった分」しか見えていないので、指摘されるまで完了したつもりでいる
- 指摘して拾い直す往復は、最初からやりきるより高くつく。**同じ作業に 2 回文脈を作る**ことになる

## 例外

- ユーザーが「今はこれだけでいい」と範囲を絞った場合
- 積んだタスクが**互いに矛盾する**場合。この場合は勝手に選ばず、どちらを採るか尋ねる（`decide_or_ask.md`）
- 前提が崩れて実行できなくなった場合。**黙って落とさず、できない理由を報告する**

## 関連

- `no_unnecessary_pausing.md`（確認が要らないなら止まらない）: 本ルールは**落とさない**こと、あちらは**止まらない**こと。落としていなくても、許可を待って止まれば進まない
- `summarize_after_each_task.md`（各作業後のサマリ）: 1 つ終えるごとに報告するが、**報告は次へ進まない理由にならない**
- `decide_or_ask.md`（自分で決めるか尋ねるか）: 矛盾する指示が積まれたときの扱い
- `concise_first_then_detail.md`（簡潔に）: 積まれた一覧も要点だけで足りる
