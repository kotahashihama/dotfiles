# PR を作るときは ship-pr を入口にする

新しく PR を作る場面では、**`/create-pr` ではなく `/ship-pr` を呼んで**ください。
これは全プロジェクト共通の規約です。

`/ship-pr` は `/create-pr` に、**プロジェクト側に深いレビューのスキルがあればその実行**と、AI レビューの周回を足したラッパーです。**`/create-pr` だけで済ませると、レビューを回すかどうかが毎回その場の判断になり、忘れれば指摘のないまま人間レビューへ出ることになります。**

## 呼び分け

| 場面 | 呼ぶもの |
| --- | --- |
| **PR を新しく作る** | **`/ship-pr`** |
| 既にある PR にレビューを回す | `/loop-ai-reviews` |
| 既にある PR を仕上げる（点検・本文の鮮度） | `/finalize-pr` |
| 担当 PR を横断で仕上げる | `/finalize-prs` |

**`/create-pr` を直接呼ぶのは、ユーザーが名指ししたときだけ。** 「レビューは要らない」と明示された場合も含みます。

## 中の個別スキルを直接呼ばない

`/ship-pr` や `/loop-ai-reviews` は、内部で複数のスキルを順に呼びます。**入口を飛ばして中を直接呼ぶと、前後の手順が落ちます。**

| 直接呼ばない | それを含む入口 |
| --- | --- |
| `/create-pr` | `/ship-pr` |
| `/request-ai-reviews` / `/wait-ci` / `/resolve-ai-reviews` | `/loop-ai-reviews` |

**例外は、入口のスキル自身がその手順として呼ぶとき。** ラッパーが順序を管理している最中は、当然中を呼びます。

### 縛るのは手段ではなく結果

**`gh` を直に叩くのも同じ違反です。** スキル名で禁じると、コマンドで同じことをする経路が抜け道になります。

| やること | 使わない | 入口 |
| --- | --- | --- |
| PR を作る | **`gh pr create`** | `/ship-pr` |
| AI レビューを起動する | **`gh pr comment --body "/ai-review"`** | `/loop-ai-reviews` |
| PR 本文を書き直す | **`gh pr edit --body`** | `/update-pr-description` |

**判定は「何を使ったか」ではなく「何が起きたか」で行う。** PR が作られたなら、経路が `gh` でもスキルを通したことにはなりません。

**例外は、入口のスキル自身が手順として叩くとき。** スキルの本文が `gh` コマンドを指定している箇所は、そのとおり実行します。

## なぜ

- **AI レビューを回す判断を毎回しないため。** 「今回は要るか」を考える余地があると、急いでいるときに落ちる。入口を1つにすれば既定で回る
- 人間のレビュアーの時間は有限で、**機械が見つけられる指摘を先に潰しておく**ほうが本題に集中してもらえる
- ラッパーは順序と打ち止めの判定を持っている。**中を直接呼ぶと、その判断ごと失われる**（指摘ゼロで止める・失敗した周を数えない等）

## 例外

- ユーザーが `/create-pr` を名指しした場合
- ユーザーが「レビューは要らない」と明示した場合（ `/ship-pr` 側の例外規定でもある）

## 関連

- `no_auto_ready_pr.md` （レビュー依頼は明示指示のみ）: **`/ship-pr` は ready 化しない**。AI レビューまで回して draft のまま止まる
- `align_skill_md_format.md` （スキルの書き方と整理）: ラッパーとプリミティブの分け方はあちらが規定する。本ルールは**呼ぶ側**をどうするか
