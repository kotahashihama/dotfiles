# GitHub へ書く文章は 1 文ごとに改行する

PR 説明・レビューコメント・返信など、**GitHub へ投稿する日本語の散文は 1 文で改行**してください。`。` が行の途中に現れない状態を保ちます。
これは全プロジェクト共通の規約です。

## 対象

Claude がユーザーに代わって GitHub へ書き込む日本語のテキスト全般。

- PR 説明（新規作成・更新のいずれも）
- レビューコメント（総括・インラインの両方）
- レビューコメントへの返信、PR コメント、issue の本文とコメント

## 期待する書き方

```markdown
<!-- ❌ NG: 1 行に複数の文が入り、`。` が行の途中にある -->
`Create` は 4 文、`Update` は 3 文を続けて発行します。トランザクションは呼び出し側が張る opt-in の仕組みなので、包み忘れると途中の失敗で行が残ります。

<!-- ✅ OK: 1 文ごとに改行し、`。` は行末だけ -->
`Create` は 4 文、`Update` は 3 文を続けて発行します。
トランザクションは呼び出し側が張る opt-in の仕組みなので、包み忘れると途中の失敗で行が残ります。
```

- **改行するのは文の区切りだけ。** 読点（`、`）では折らない
- **箇条書き・表のセルの中も同じ。** セル内に 2 文入るなら、そのセルは長すぎるので分ける
- GitHub の issue / PR / discussion では、**単一改行がそのまま改行として描画される**。1 文ごとに行が分かれ、長い段落も追いやすくなる
- 段落を分けたいところでは**空行**を入れる。行間が広がって区切りが見える
- **リポジトリ内の `.md` ファイルは挙動が違う**（単一改行は空白になる）。本ルールが対象にするのは GitHub 上の投稿だけ

## なぜ

- **差分が文単位で出る。** 1 文 1 行なら、後から本文を直したときに変えた文だけが差分に出る。1 行に詰めると段落全体が差し替わったように見え、レビュアーはどこが変わったか読み直すことになる
- **レビューコメントの引用が文単位でできる。** 相手が返信で一部を引用するとき、行単位で選べる
- 折り返し位置が読み手の画面幅で変わるため、**書き手が段落の見た目を制御しても意味がない**。文の区切りで折るほうが構造として安定する

## 例外

- **英語の文章**は対象外（英語圏の慣習に従う）
- **コードブロック・引用の中身**はそのまま。原文の改行を変えない
- **コマンドコメント**（`/ai-review` 等）は本文をコマンド 1 行に保つ（`github_command_comments.md`）
- ユーザーが文面を指定して「これをそのまま投稿して」と指示した場合

## 関連

- `github_note_generated_by_claude.md`（生成者表示）: どちらも GitHub へ書く文章の書式を定める
- `github_cross_repo_reference.md`（他リポジトリの参照）: 同上
- `github_command_comments.md`（コマンドコメントの別扱い）: 本ルールの適用外を定める
- `/review-pr` / `/create-pr` / `/update-pr-description` / `/resolve-ai-reviews`: 本ルールが土台で、各スキルは投稿先固有の事情を上乗せする
