# GitHub では、伝わる形を選んで書く

PR 本文・コメント・レビュー返信では、**散文で書くと長くなるものを別の形へ畳んで**ください。GitHub が解釈する記法は、どれも**読む負担を下げるため**にあります。
これは全プロジェクト共通の規約です。

**増やすためではなく、減らすために使う。** 飾りとして足すと、本当に見てほしいものが埋もれます。

## 手段の選び方

| 手段 | 使う場面 | 詳細 |
| --- | --- | --- |
| **表** | 同じ観点の項目が 3 件以上 | `concise_first_then_detail.md` |
| **Mermaid** | 列挙から読み取れない構造・関係・流れ | 同上 |
| **Alert** | **読み飛ばすと事故る 1〜2 点** | 下記 |
| **`<details>`** | **その場で開ける形で長い実体を置く** | 下記 |
| **脚注** | **本筋から外れる 1 行の補足** | 下記 |
| **別コメント** | 本文と独立に参照される情報のかたまり | `/create-pr` / `/update-pr-description` |

## Alert は 3 種だけ使う

GitHub には 5 種ありますが、**使うのは 3 種**に絞ります。選択肢が多いと毎回迷い、迷った末に強い方を選びがちになります。

| 種類 | 使う場面 |
| --- | --- |
| `NOTE` | **生成者表示に占有されている**（`github_note_generated_by_claude.md`）。他の用途に使わない |
| `IMPORTANT` | **知らないと動かせない・順序を誤ると壊れる**（マージ順、DB の再生成、前提の設定） |
| `WARNING` | **既存の挙動が壊れうる**（この経路だけ並行更新に弱い、この条件で値が落ちる） |

`TIP` は PR に書く場面が無く、`CAUTION` は `WARNING` と役割が重なるので使いません。

**生成者表示を除いて 1 投稿に 1 つまで。** GitHub 自身が「1 記事あたり 1〜2 個」「連続して置かない」としており、生成者表示の `NOTE` が既に 1 枠を使っています。

**Alert は他の要素の中へネストできません。** 表のセル・箇条書きの中には置けないので、置くなら独立した位置に。

## `<details>` と別コメントを使い分ける

どちらも「本文を汚さずに詳細を置く」手段なので、**基準を持たないと毎回迷います**。

| | `<details>` | 別コメント |
| --- | --- | --- |
| 置く場所 | **その情報が要る節の直下** | 本文の外 |
| 読み手 | **その節を読んでいる人が、その場で開く** | 必要になった人が探して開く |
| 例 | テスト出力の抜粋、失敗したときのログ、SQL の全文 | API 契約の全文、調査ログ、他リポジトリ向けの申し送り |

**`<summary>` には中身が分かる名前を付ける。** 「詳細」では開くまで判断できません。

**畳んだ中身にも本文と同じ基準を当てる。** 畳めば何を書いてもよいことにはなりません。

## 脚注は着地位置に注意する

**GitHub は脚注を描画結果の末尾へ集めます。** PR 本文では**生成者表示より後ろ**に出るので、テンプレの節構成とは無関係の位置に着地します。

そのため、**節の中で読まれる必要がある補足には使わない**。使うのは、読み飛ばしても本筋が通る 1 行だけです。

括弧書きで済むなら括弧書きにする。**脚注は読み手に往復させる**ので、1 行の補足に見合わないことが多い。

## なぜ

- **レビュアーは差分を読むために来ており、本文を読むのは前段**。前段が長いほど、本題に入るまでの負担が増える
- 記法はどれも**読む順序を作る**もの。Alert は「先に読め」、`<details>` は「後で読め」、脚注は「読まなくてよい」を意味する。**意味と合わない使い方をすると、読み手の判断を狂わせる**
- 強調は**相対的**にしか働かない。全部を強調すると、何も強調していないのと同じになる

## 例外

- ユーザーが形式を指定した場合
- **コマンドコメント**は本文をコマンド 1 行に保つ（`github_command_comments.md`）

## 関連

- `concise_first_then_detail.md`（簡潔に）: **表と Mermaid の使い分けはあちら**。本ルールは GitHub でしか使えない手段を足す
- `github_note_generated_by_claude.md`（生成者表示）: **`NOTE` を占有している**。他の Alert と混ざらないよう、用途を分ける
- `github_one_sentence_per_line.md`（1 文ごとに改行）: あちらは**文の表記**、本ルールは**構造の選び方**
- `/create-pr` / `/update-pr-description`: 本ルールが土台で、スキルは PR 固有の事情（テンプレの節構成、別コメントへの切り出し）を上乗せする
