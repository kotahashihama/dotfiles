# GitHub へ書き込む文章の末尾に生成者表示を添える

Claude が GitHub 上に投稿・更新する文章には、**末尾に GitHub Note アノテーションで生成者表示を添えて**ください。
これは全プロジェクト共通の規約です。

## 対象

Claude がユーザーに代わって GitHub へ書き込むテキスト全般。

- PR 説明（新規作成・更新のいずれも）
- PR コメント（issue comment）
- レビューコメントへの返信（inline reply）
- issue の本文・コメント
- Discussion の投稿

## 形式

本文の末尾に**空行を 1 行**挟み、以下のブロックを置く。

```
<本文>

> [!NOTE]
> このコメントは Claude Code で作成されています。
```

- PR 説明の場合は主語を変える: `この PR 説明は Claude Code で作成されています。`
- **モデル名（Opus / Sonnet 等）ではなくクライアント名 `Claude Code` を使う**。モデル名は起動ごとに揺れるが、書き手はいずれも Claude Code なので統一する
- **必ず末尾**に置く。冒頭に置くと読み手が本文本体に辿り着くまでにメタ情報を読まされる
- 既存の投稿に旧フォーマットの生成者表示があれば、この Note ブロック 1 つに正規化する

## 期待する挙動

- `gh pr comment` / `gh pr edit --body` / `gh api ... /replies` 等で投稿する前に、本文末尾へ Note ブロックを足したか確認する
- ハッシュだけを返す短い返信でも省略しない。Note はブロッククォートで本文と改行分離されるため、**1 行目からのハッシュ機械抽出を妨げない**
- 既存投稿を更新するときも、Note が末尾に残っているかを確認する（本文を差し替えて消してしまわない）

## 禁止する挙動

- Note を付けずに GitHub へ投稿すること
- 本文の冒頭や中間に置くこと
- `Claude Opus 5` のようなモデル名を書くこと
- 「AI が書きました」等の独自文言に置き換えること（文言は上記で固定）

## なぜ

- 人間のレビュアーが**書き手を判別できる**ようにするため。人が書いた文章と混ざると、指摘の重みや確認の仕方を読み手が判断できない
- 文言とクライアント名を固定することで、**投稿の出どころが機械的に追える**（後から一括検索・集計ができる）
- 末尾固定にすることで、レビュアーは本文本体を先に読める

## 例外

- ユーザーが「Note は不要」と明示した場合
- ユーザーが文面を指定して「これをそのまま投稿して」と指示した場合（ユーザーの言葉として投稿するため）
- `git commit` のメッセージ・PR タイトル（こちらは `Co-Authored-By` トレーラーが役割を担う）
- **コマンドコメント**（`/ai-review` 等、ワークフローが本文を検知するもの）。Note を足すと検知が壊れる（`github_command_comments.md`）

## 関連

- `github_command_comments.md`（コマンドコメントの別扱い）: 本ルールの適用外を定める。宛先が人ではなく機械のコメントには Note を付けない
- `no_auto_reply_human_review_comments.md`（人間コメントへの自動返信禁止）: そもそも投稿してよいかを規定。本ルールは**投稿すると決まった後の書式**を規定する
- `/create-pr` / `/update-pr-description` / `/resolve-ai-reviews` の各スキルにも同じ規定がある。本ルールはスキル経由でない自然文依頼の経路を含めて横断的に適用する
- `github_cross_repo_reference.md`（他リポジトリの PR / issue の書き方）: どちらも GitHub へ書く文章の書式を定める
