# マージは、検査を通すまで終わっていない

ベースブランチを取り込んだら、衝突が0件でも、手で解決した後でも、lint・型検査・テストを通してください。git が見ているのはテキストの行だけで、参照の整合は見ていません。push する先で CI がテストを回すなら、手元で待つのは lint と型検査までです。
これは全プロジェクト共通の規約です。

**ベースを取り込んだら、`~/.claude/references/verify_merge_with_checks.md` を読む。** git が見逃す2つの形（衝突しなかった参照切れ・解決したつもりの宣言と本文の食い違い）、直す場所、消したはずの記述が戻っていないかの確かめ方、禁止する挙動はそちらにある。

## 関連

- `no_rebase_under_human_review.md` （レビュー中は履歴を書き換えない）: あちらは内容が消える話（rebase がマージコミットを平坦化する）、本ルールは内容は残るが参照先が動く話
- `verify_the_check_worked.md` （検査が成立していたかを疑う）: **成功表示を根拠にしない**という同じ形。本ルールはその適用場面の1つ
- `keep_records_current.md` （変えたら説明も直す）: マージで差分が動いたら、PR 説明の鮮度も見る
