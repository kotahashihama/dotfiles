# マージは、検査を通すまで終わっていない

ベースブランチを取り込んだら、**衝突が 0 件でも型検査・lint・テストを通して**ください。通るまでがコンフリクト解消です。
これは全プロジェクト共通の規約です。

**`git merge` の成功は「同じ行を触っていない」ことしか意味しません。** 片方が動かした対象を、もう片方が使い続けていても、**触った行が重ならなければ git は何も言いません**。

## git が見逃す 3 つの型

| 型 | 何が起きているか | 検出するもの |
| --- | --- | --- |
| **参照切れ** | 片方がファイルや型を移動 / 削除し、もう片方が**新しく足したファイル**から古い名前を参照している | **型検査** |
| **死んだコード** | 片方が処理を切り出し、もう片方がその参照元を作り変えた。import と変数が使われないまま残る | **lint** |
| **契約の不一致** | 片方が引数・型の値・既定値を変え、もう片方のテストや呼び出しが古い形のまま | **型検査 / テスト** |

**どれも「新しく足したファイル」で起きます。** 既存ファイルの同じ行なら git が止めますが、**片方が新設したファイルは衝突の対象になりません**。

実際に、雑務系の PR 群でベースを取り込んだところ、**文面上の衝突が 0 件だったブランチでも参照切れ・死んだ import・テストの型不一致が見つかりました**。いずれも `git merge` は成功と表示していました。

## 通す順序

**軽いものから。落ちた層がそのまま原因の場所になります。**

| 順 | 検査 | 見つかるもの |
| --- | --- | --- |
| 1 | **lint / format** | 死んだ import と変数。数秒で終わる |
| 2 | **型検査** | 参照切れ、契約の不一致。**テストより先に出る** |
| 3 | **テスト** | 振る舞いの変化 |

**テストだけで済ませない。** 参照切れは**そのファイルを通るテストが無ければ出ません**。型検査は全ファイルを見るので、こちらのほうが網羅的です。

**逆に、型検査だけでも足りません。** 片方が仕様を変え、もう片方がその仕様に依存していた場合、型が合っていても振る舞いが変わります。

## 遅れが大きいほど確率が上がる

**「衝突が無かったから大丈夫」は、遅れているブランチほど成り立ちません。** ベースが進んだぶんだけ、動いた対象が増えています。

```bash
git rev-list --count HEAD..origin/<base>   # 何本遅れているか
```

**遅れが大きいなら、検査を飛ばす判断をしない。** 逆に 0 本なら取り込む必要そのものがありません。

## 直したものは、切り出し先まで追う

**片方が仕様を変え、もう片方がその処理を別ファイルへ切り出していたとき、直す場所は切り出し先です。**

呼び出し側だけを新しい形に合わせると、**中身が古いまま通ってしまいます**。型が合うので検査も止めません。

- 切り出し先の実装を、動いた仕様に合わせる
- **その切り出し先のテストも同時に直す**。古い契約のまま残ると、検査が空振りになる

## 禁止する挙動

- **衝突 0 件を理由に検査を飛ばすこと**。git の成功は行の重なりしか見ていない
- **テストだけで済ませること**。参照切れは、そのファイルを通るテストが無ければ出ない
- **型検査だけで済ませること**。仕様が変わっていれば、型が合っても振る舞いが変わる
- **呼び出し側だけ新しい形に合わせること**。切り出し先の中身が古いまま通る
- **lint の警告を残したままマージすること**。死んだ import はマージで生まれやすく、放置すると次のマージで埋もれる
- マージの成功表示を、**内容が保たれた証拠として扱うこと**

## なぜ

- git が見ているのは**テキストの行**であって、参照の整合ではない。**別ファイルなら、何を壊していても衝突にならない**
- 見逃した不整合は**マージした本人にしか直せない**。他の人が気づくのは CI か、最悪の場合デプロイ後になる
- 検査は数分で終わる。**取り込んだ直後が最も安く、時間が経つほど「何を変えたか」を思い出す作業が乗る**

## 例外

- ベースからの遅れが 0 本のとき（取り込む必要が無い）
- 検査の走らないリポジトリ（設定・ドキュメントのみ）。この場合も**参照先の実在**は確かめる

## 関連

- `no_rebase_under_human_review.md`（レビュー中は履歴を書き換えない）: あちらは**内容が消える**話（rebase がマージコミットを平坦化する）、本ルールは**内容は残るが参照先が動く**話。**検出手段も違う**——あちらは差分の比較、こちらは型検査と lint
- `verify_the_check_worked.md`（検査が成立していたかを疑う）: **成功表示を根拠にしない**という同じ形。あちらは「返ってきたものを読み違えていないか」を持ち、本ルールはその適用場面の 1 つ
- `split_and_stack_prs.md`（大きい変更は分ける）: **マージ順を書くために依存を実体で判定する**手順を持つ。本ルールは取り込んだ後の話
- `keep_records_current.md`（変えたら説明も直す）: マージで差分が動いたら、PR 説明の鮮度も見る
