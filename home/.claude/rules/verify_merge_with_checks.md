# マージは、検査を通すまで終わっていない

ベースブランチを取り込んだら、**衝突が 0 件でも、手で解決した後でも、型検査・lint・テストを通して**ください。通るまでがコンフリクト解消です。
これは全プロジェクト共通の規約です。

**git が見ているのはテキストの行だけです。** 参照の整合は見ていないので、**成功表示は「内容が保たれた」ことを意味しません**。

## git が見逃す 2 つの形

| 形 | 何が起きているか | 検出するもの |
| --- | --- | --- |
| **衝突しなかった** | 片方が動かした対象を、もう片方が**新しく足したファイル**から参照している。既存ファイルの同じ行なら git が止めるが、新設ファイルは衝突の対象にならない | **型検査** |
| **衝突を手で解決した** | **同じ関数の中で、宣言は片側・本文はもう片側**が採られる。マーカーは消えるので、直したつもりで壊れている | **型検査** |

実際に、雑務系の PR 群でベースを取り込んだところ、**文面上の衝突が 0 件だったブランチでも参照切れ・死んだ import・テストの型不一致**が見つかりました。別の PR では衝突を解決した後、**引数の宣言だけが古い側から採られ、追加された引数が未定義のまま参照される**状態になっていました。

## 通す順序

**軽いものから。落ちた層がそのまま原因の場所になります。**

| 順 | 検査 | 見つかるもの |
| --- | --- | --- |
| 1 | **lint / format** | 死んだ import と変数。数秒で終わる |
| 2 | **型検査** | 参照切れ、契約の不一致。**テストより先に出る** |
| 3 | **テスト** | 振る舞いの変化 |

**どれか 1 つでは足りません。** 参照切れは**そのファイルを通るテストが無ければ出ず**、逆に仕様が変わっていれば**型が合っても振る舞いが変わります**。

**遅れが大きいほど確率が上がる。** ベースが進んだぶんだけ動いた対象が増えるので、`git rev-list --count HEAD..origin/<base>` が大きいなら検査を飛ばさない。

## 直す場所は、切り出し先

片方が仕様を変え、もう片方がその処理を別ファイルへ切り出していたとき、**呼び出し側だけ新しい形に合わせると中身が古いまま通ります**（型が合うので検査も止まらない）。切り出し先の実装と**そのテスト**を同時に直す。

## 禁止する挙動

- **衝突 0 件を理由に検査を飛ばすこと**。git の成功は行の重なりしか見ていない
- **衝突を手で解決したことを、解決できた証拠として扱うこと**。マーカーが消えても内容は壊れうる
- **検査を 1 つで済ませること**。型検査だけでもテストだけでも抜ける
- **呼び出し側だけ新しい形に合わせること**。切り出し先の中身が古いまま通る
- **lint の警告を残したままマージすること**。死んだ import はマージで生まれやすい

## なぜ

- git が見ているのは**テキストの行**であって参照の整合ではない。**別ファイルなら、何を壊していても衝突にならない**
- 衝突を解決する操作は**行単位**なので、同じ関数の宣言と本文が別の側から採られうる。**人が「解決した」と思う単位と git の単位が違う**
- 見逃した不整合は**マージした本人にしか直せない**。他の人が気づくのは CI か、最悪デプロイ後
- 検査は数分で終わる。**取り込んだ直後が最も安く、時間が経つほど「何を変えたか」を思い出す作業が乗る**

## 例外

- ベースからの遅れが 0 本のとき（取り込む必要が無い）
- 検査の走らないリポジトリ（設定・ドキュメントのみ）。この場合も**参照先の実在**は確かめる

## 関連

- `no_rebase_under_human_review.md`（レビュー中は履歴を書き換えない）: あちらは**内容が消える**話（rebase がマージコミットを平坦化する）、本ルールは**内容は残るが参照先が動く**話
- `verify_the_check_worked.md`（検査が成立していたかを疑う）: **成功表示を根拠にしない**という同じ形。本ルールはその適用場面の 1 つ
- `split_and_stack_prs.md`（大きい変更は分ける）: あちらは**取り込む前**の依存判定、本ルールは**取り込んだ後**の検証
- `keep_records_current.md`（変えたら説明も直す）: マージで差分が動いたら、PR 説明の鮮度も見る
