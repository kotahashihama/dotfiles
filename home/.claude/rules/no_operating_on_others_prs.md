# 他人の PR は触らない

PR へ何かする前に、**それが誰の PR かを確かめて**ください。作成者がユーザー本人でなければ、状態を読むだけに留めます。
これは全プロジェクト共通の規約です。

```bash
gh pr view <PR> --json author -q '.author.login'
```

**一覧から入るときこそ確かめる。** `gh pr list` は番号と title しか見せないので、**全部が自分のものに見えます**。

## 触ってよい範囲

| 作成者 | できること |
| --- | --- |
| **ユーザー本人** | 通常どおり（各ルールの範囲で） |
| **それ以外** | **読むだけ。** 状態の確認・レビュー内容の把握・報告 |

「それ以外」で禁じるのは、**PR に痕跡が残るすべての操作**です。

- ブランチへの push（コミット・マージ・force push）
- ready 化 / draft へ戻す
- レビュアーの追加・削除
- レビューコメントへの返信・リアクション・Resolve
- 本文やタイトルの編集
- スタックのリンク・解除

**判定は「何を使ったか」ではなく「何が起きたか」で行う。** ブランチを checkout して直にコミットしても、
その PR へ push したことに変わりはありません。スキルを通していないから対象外、にはならない。

## 見分けがつかないときは何もしない

**PR は自分のものだという前提を、無意識に置きがちです。** 次のどれかに当たったら、確かめるまで手を出さない。

| 兆候 | 実際にあること |
| --- | --- |
| **draft のまま置かれている** | **別の人が意図して止めている**。ready にする判断はその人のもの |
| 自分が書いた覚えのない実装が入っている | 別の人の作業 |
| reviewer に自分が入っている | **レビューする側**であって、直す側ではない |
| ブランチ名の流儀が自分と違う | 別の人が切った |

**「整ったら〜していい」という許可は、自分の PR についてのもの**です。範囲を確かめずに他人の PR へ広げない。

## 禁止する挙動

- **作成者を確かめずに PR を操作すること**
- 一覧の番号と title だけを見て、**全部を自分のものと前提すること**
- **draft を「ユーザーの作業中」と読むこと**。別の人の作業中かもしれない
- 他人の PR に指摘が付いているのを見て、**代わりに直すこと**。直す判断は作成者のもの
- 他人の PR の reviewer が揃っていないのを見て、**補うこと**。誰に依頼するかは作成者が決める
- **`gh` の成功表示だけで反映を判断すること**。`gh pr edit --add-reviewer` は 422 を握り潰して URL を返すため、通ったように見えて入っていないことがある

## なぜ

- **通知は取り消せない。** ready 化もレビュー依頼も、相手の時間を奪ったことは戻らない。履歴にも「やって、戻した」が残る
- **draft は合図**であって未完成の印ではない。デザイン確認待ち・別の作業と揃えたい等、**作成者にしか分からない事情**がある
- **自分の PR かどうかは 1 コマンドで分かる。** 確かめる手間より、間違えたときの後始末のほうがはるかに高い
- 他人の PR を直すのは親切に見えるが、**その人の手元と競合する**。force push でやり直しになることもある

## 例外

- ユーザーが「この PR を触って」と**番号を名指しで**指示した場合。「全部やって」のような広い依頼は名指しに当たらない
- ユーザーがレビュアーとして依頼された PR へ、**レビューを書くこと**（`/review-pr`）。これは読む側の行為で、本ルールの対象外
- **bot が作った PR**（renovate 等）。人の成果物ではなく、こちらが仕上げる前提で作られている（`/resolve-renovate-pr`）

## 関連

- `no_auto_ready_pr.md`（レビュー依頼は明示指示のみ）: あちらは**いつ**やるか、本ルールは**誰の PR か**。**本ルールが先に効く**——他人の PR なら、指示があってもまず作成者へ確かめる
- `no_auto_commit.md`（コミット・プッシュは明示指示のみ）: 同上。指示があっても、他人のブランチなら別の判断が要る
- `no_rebase_under_human_review.md`（レビュー中は履歴を書き換えない）: あちらは**コメントの投稿者**で判定する。本ルールは**PR の作成者**。別の軸なので両方見る
- `decide_or_ask.md`（自分で決めるか尋ねるか）: 取り消せない操作は尋ねる。**他人の PR への操作はすべてこれに当たる**
