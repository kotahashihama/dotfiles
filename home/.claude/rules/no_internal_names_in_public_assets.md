# 公開リポジトリの資産に社内固有名を書かない

`~/.claude/` の実体は dotfiles リポジトリで、そのうち **`home/` 配下は公開リポジトリです**。書いたものがそのまま外から読めます。
これは全プロジェクト共通の規約です。

**公開してしまうと取り消せません。** 消すには履歴の書き換えが要り、それでも既に読まれた可能性は消えません。

## 書けるもの / 書けないもの

| 書ける | 書けない |
| --- | --- |
| 書式・構造・判定基準 | **リポジトリ名・GitHub ID・プロダクト名・社内 URL** |
| プレースホルダ（`OWNER/REPO`） | 実際に動かした出力をそのまま貼ったもの |

**最も混入しやすいのは出力例です。** 実際に動かした結果を貼るのが自然なので、コピーしたまま残ります。**例を書いたら固有名が混じっていないか読み返す。**

実データを含む例をどうしても残したいなら `private/` 側へ置く。

## 実体がどちら側かを確かめる

`~/.claude/` からはシンボリックリンク越しに見えており、**public / private の区別が付きません**。

| 実体の置き場 | 公開 | 固有名 |
| --- | --- | --- |
| `home/.claude/`（rules / skills / hooks / agents / settings.json / CLAUDE.md） | **される** | **書けない** |
| `private/.claude/` と `private/.claude-memory/` | されない | 書ける |

**スキルは public と private の両方にあります。** `~/.claude/skills/` からはスキル単位でリンクされているので、**編集したファイルの実体を `readlink -f` で確かめる**。

## フックを前提にしない

`pre-commit` が走査していますが、**フックに気づかせてもらう前提で書かない**でください。止められてから直すのは手戻りですし、**フックの無い経路では素通りします**。

| 経路 | フックの効き |
| --- | --- |
| dotfiles への `git commit` | 効く |
| 他リポジトリの公開ファイル・Gist | 効かない |
| **会話への出力** | **効かない** |

## なぜ

- 公開は**取り消せない操作**。固有名は1度出たら、履歴を書き換えても読まれた事実は消えない
- 混入は「悪意」ではなく「**自然な手順の結果**」として起きる。実際に動かした出力を例に貼るのは合理的な行為で、そこに固有名が乗っている
- 機械的な検査と書く側の意識は**別の穴を塞いでいる**。片方があるからもう片方が要らない、という関係ではない

## 例外

- `private/` 側へ置く場合
- ユーザーが「この例はそのまま載せてよい」と明示した場合

## 関連

- `no_secret_values_in_output.md`（秘匿値を出力しない）: **秘匿値は固有名より厳しく扱う**。あちらはファイルに限らず**あらゆる出力**が対象。本ルールは公開リポジトリのファイルが対象
- `ask_before_editing_claude_assets.md`（設定は尋ねてから）: 資産を編集してよいかの判断と、編集後の永続化を規定する。本ルールは**何を書いてよいか**
