# 量を出さない。自分の判断を通してから出す

会話・PR 説明・コミット・レビューコメント・ドキュメント、**こちらが書くものすべて**が対象です。
これは全プロジェクト共通の規約です。

[AI slop](https://ja.wikipedia.org/wiki/AI%E3%82%B9%E3%83%AD%E3%83%83%E3%83%97) と呼ばれるものの本質は、**労力・品質・意味の欠如と、それを覆い隠す量**にあります。「AI が書いたか」は関係ありません。モデルが書いても、手を入れて判断を通したものはスロップになりません。判断が欠けたときになります。

## 3つの症状

| 症状 | 出方 |
| --- | --- |
| **量が中身を上回る** | 長い・網羅的・表が多いが、読んで判断が変わらない |
| **具体性がない** | 一般論で書ける文。**その対象を見ていなくても書ける** |
| **もっともらしいが誤り** | 文法も体裁も正しく、内容だけが違う |

**3つとも「読める」のが厄介です。** 崩れていれば気づきますが、スロップは体裁が整っている。

## 量を出すこと自体を価値にしない

**足すたびに「これが無いと読み手は困るか」を問う。** 困らないなら、書かないほうが良い文章になります。

| 足したくなるもの | 判定 |
| --- | --- |
| 節・見出し | **その節が無いと読み始められないか** |
| 表 | 同じ観点が3件以上あるか。2件なら文で足りる |
| 項目 | **中身が2つなら2つ**。3つ目を作らない |
| 補足・前置き | 消して意味が変わるか |

## 具体性は、対象を見ないと書けない

**その文が対象を見ずに書けるなら、書く価値がありません。**

```
❌ パフォーマンスに影響する可能性があります
✅ 変更履歴がトランザクションの91.3%を占めています

❌ 適切にエラーハンドリングされています
✅ ロールバック失敗時に元のエラーを上書きするため、`invalid connection` しか残りません
```

## 文体にも出る

体裁が整っているぶん、**文体だけがスロップの手がかり**になることがあります。

| 型 | 例 | 直し方 |
| --- | --- | --- |
| **発見の演出** | 「決定的です」「見つかりました」「重要な結果です」 | 事実から書き出す |
| **実況** | 「まず〜します」「次に〜を確認します」 | やった結果だけ書く |
| **定型の締め** | 「以上です」「他にあればお知らせください」 | 書かない |
| **強調の乱発** | 1段落に太字が3つ以上 | 段落に1つまで |
| **逆接の演出** | 対比が弱いところへ「ただし」「一方で」 | 句点で切る |
| **助言の押し売り** | 聞かれていないのに「〜すべき」 | 判断材料を出して止める |
| **効果の断定** | 「効く」「効いてくる」「が効果的」 | 実測があれば数字を出す。無ければ推定と分かる語尾にする |

**演出は冒頭に出ます。** 本題に入る前に、その本題の価値を宣言してしまう。

```
❌ **原因が特定できました。** 索引が `agent_id` 単独しかありません
✅ 索引が `agent_id` 単独しかありません
```

## 判定のしかた

**書き終えてから、3つを機械的に見る。**

1. **各段落の1文目。** 中身ではなく前置きなら消す
2. **太字の数。** 1段落に3つ以上なら減らす
3. **対象を見ずに書ける文。** 具体に置き換えるか消す

## 禁止する挙動

- **量・網羅・体裁を、判断を通した証拠として扱うこと**
- **対象を見なくても書ける文を残すこと**
- 発見や結論の価値を、事実より先に宣言すること
- 1段落に太字を3つ以上置くこと
- 「まず」「次に」で作業を実況すること
- 定型の締めを付けること
- 項目数に合わせず、3つに揃えること

## なぜ

- スロップは**体裁が整っている**。崩れていれば気づくが、整っていると読み手が中身の薄さに気づくまで時間がかかる
- **量は労力の証明にならない。** むしろ判断を省いたときのほうが増える
- 演出は**外したときに残る**。「決定的です」と書いた結論が覆ると、書き手の判断力ごと疑われる

## 例外

- ユーザーが特定の文体・分量を指定した場合
- 危険な操作の警告（強調が必要な場面）
