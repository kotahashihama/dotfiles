# AI が書いたと分かる文体で書かない

会話・PR 説明・コミット・レビューコメント・ドキュメント、**こちらが書くものすべて**が対象です。
これは全プロジェクト共通の規約です。

**中身が良くても、文体で読む気が削がれます。** 読み手は1行目で「機械が書いたな」と判じ、そこから先を流し読みします。判断材料として正しくても、読まれなければ届きません。

## 型と直し方

| 型 | 例 | 直し方 |
| --- | --- | --- |
| **発見の演出** | 「決定的です」「見つかりました」「重要な結果です」 | 事実から書き出す |
| **実況** | 「まず〜します」「次に〜を確認します」 | やった結果だけ書く |
| **定型の締め** | 「以上です」「他にあればお知らせください」 | 書かない |
| **強調の乱発** | 1段落に太字が3つ以上 | 段落に1つまで |
| **逆接の演出** | 対比が弱いところへ「ただし」「一方で」 | 句点で切る |
| **助言の押し売り** | 聞かれていないのに「〜すべき」 | 判断材料を出して止める |
| **効果の断定** | 「効く」「効いてくる」「が効果的」 | 実測があれば数字を出す。無ければ推定と分かる語尾にする |

**演出は冒頭に出ます。** 本題に入る前に、その本題の価値を宣言してしまう。

```
❌ **原因が特定できました。** 索引が `agent_id` 単独しかありません
✅ 索引が `agent_id` 単独しかありません
```

## 語を狩らない。意味で判定する

**表の「例」は手がかりであって、置換の一覧ではありません。** 同じ語が別の意味で使われます。

| 語 | 対象になる意味 | 対象外の意味 |
| --- | --- | --- |
| **効く** | 効果がある（「この対策が効く」） | **適用される・発動する**（「本ルールが先に効く」「`paths` が効かない」） |
| ただし | 対比が弱いのに置く | 本当に逆接 |
| **すべき** | 聞かれていないのに助言する | 規約として求める |

実際に、ルール群で「効く」を数えたら大半が**適用の意味**でした。一括置換すれば、そちらまで壊れます。

**同じ理由で、逆向きにも壊れます。** 断定の語を一律に弱めると、実測が裏にあるものまで見込みの話になります（`base_records_on_measurements.md`）。

## 判定のしかた

**書き終えてから、3つを機械的に見る。**

1. **各段落の1文目。** 中身ではなく前置きなら消す
2. **太字の数。** 1段落に3つ以上なら減らす
3. **断定している箇所。** 裏に実測があるか。無いなら語尾を推定に変える

## 禁止する挙動

- 発見や結論の価値を、事実より先に宣言すること
- 1段落に太字を3つ以上置くこと
- 「まず」「次に」で作業を実況すること
- 定型の締めを付けること
- **効果を「効く」で断定すること**。実測があるなら数字を出す
- **表の例を置換の一覧として使うこと**。同じ語の別の意味まで巻き込む

## なぜ

- 文体は**中身より先に読まれる**。演出が冒頭にあると、そこで読み手の期待が決まる
- 演出は**外したときに残る**。「決定的です」と書いた結論が覆ると、書き手の判断力ごと疑われる
- 強調は**相対的**にしか働かない。全部を強調すると、何も強調していないのと同じになる

## 例外

- ユーザーが特定の文体を指定した場合
- 危険な操作の警告（強調が必要な場面）

## 関連

- `no_ai_slop.md`（量を出さない）: **元は1本だった。** あちらは**量と中身**、本ルールは**表現**。判断材料として正しくても AI っぽい文体、は成立する
- `base_records_on_measurements.md`（記録は実測に基づける）: **断定と推定の語尾の使い分け**はあちらが定める。本ルールは「効果の断定」という型を挙げるだけ
- `concise_first_then_detail.md`（簡潔に）: あちらは**量**、本ルールは**文体**
- `plain_language_explanation.md`（噛み砕いた説明）: **業界で通っている語を使う**のはあちら。本ルールは語ではなく言い回しを扱う
