# AI が書いたと分かる文体で書かない

会話・PR 説明・コミット・レビューコメント・ドキュメント、**こちらが書くものすべて**が対象です。
これは全プロジェクト共通の規約です。

**中身が良くても、文体で読む気が削がれます。** 読み手は1行目で「機械が書いたな」と判じ、そこから先を流し読みします。判断材料として正しくても、読まれなければ届きません。

## 型と直し方

| 型 | 例 | 直し方 |
| --- | --- | --- |
| **発見の演出** | 「決定的です」「見つかりました」「重要な結果です」 | 事実から書き出す |
| **実況** | 「まず〜します」「次に〜を確認します」 | やった結果だけ書く |
| **定型の締め** | 「以上です」「他にあればお知らせください」 | 書かない |
| **強調の乱発** | 1段落に太字が3つ以上 | 段落に1つまで |
| **要らない強調** | 主張の中心を反射で太字にする（「〜が、**計算で出せる**」） | 下記の2つを問い、どちらも外れるなら外す |
| **逆接の演出** | 対比が弱いところへ「ただし」「一方で」 | 句点で切る |
| **助言の押し売り** | 聞かれていないのに「〜すべき」 | 判断材料を出して止める |
| **効果の断定** | 「効く」「効いてくる」「が効果的」 | 実測があれば数字を出す。無ければ推定と分かる語尾にする |
| **対句の反復** | 短い断定文を並べる（「〜しました」「〜変わりません」） | 1文へ畳む。片方が他の節と重複していれば落とす |
| **要らない否定** | 肯定の直後に裏返しを置く（「書き込み。**組み立てではない**」） | 消す。下記の判定を通す |
| **比喩で言い換える** | 「手で配る」「1つずつ塞ぐ」「膜が被さる」 | **動作をそのまま書く**（「経路ごとに更新処理を呼ぶ」「呼び出しを足す」） |

**演出は冒頭に出ます。** 本題に入る前にその本題の価値を宣言してしまう。

```
❌ **原因が特定できました。** 索引が `agent_id` 単独しかありません
✅ 索引が `agent_id` 単独しかありません
```

**対句は、書いた側には歯切れよく見えます。** 同じ長さの断定文が並ぶとリズムが出るので、**中身が増えていなくても文章が締まった感じになります**。

```
❌ 素通りする側を絞りました
   挙動は変わりません
✅ この PR では素通りする側をフィルタリングする形で修正しています
```

**片方は他の節と重複していることが多い。** 上の「挙動は変わりません」は影響範囲の節にあり、概要では要りません。

**検査があります。** dotfiles の `scripts/lint_docs.sh` を通すと、`suiko` が `antithesis_repetition` として拾います。手で探す前に回してください。

## 肯定で言えることに、否定を足さない

**「A。Bではない。」の B は、たいてい A から出てきます。** 書いた側は対比を作ったつもりですが、読み手は同じことを2度受け取ります。

```
❌ 書き込み。組み立てではない
✅ 書き込み

❌ 落ちる理由は常にメモリで、時間ではない
✅ 落ちる理由は常にメモリ
```

**判定は「消したとき、読み手が誤った推測をするか」。**

| 消す | 残す |
| --- | --- |
| **直後の表や数字が、その否定を示している** | 読み手が自然に持つ誤解を潰している |
| 肯定の側が**排他的**（「常に〜」「〜そのもの」） | 肯定だけでは**別の読みも成立する** |

**「A ではなく B」の1文形も同じ判定です。** 「レンジではなく個々のハッシュ」は読み手が実際にレンジを使いうるので残り、「分離は設計ではなく〜」は誰も設計だと言っていないので落ちます。

**形で一律に禁じない。** ルール群とスキルで `ではなく` を数えたら129件あり、抽出した12件はすべて残す側でした。

**否定しか書いていない文は、言い換える。** 「書き込みが終わった時間ではない」は**何であるか**を言っていないので、読み手が自分で埋めることになります。「接続が切れるまでの時間」と書く。

**対句の反復と紛らわしいですが、別です。** あちらは**別の主張が2つ**並んでおり、1文へ畳むか、片方が他の節と重複していれば落とす。こちらは**主張とその裏返しで中身が1つ**なので、裏返しを消す。

## 強調は、2つのどちらかを満たすときだけ

**1段落に1つでも、要らない強調はあります。** 密度だけを見ていると、主張の中心を反射で太字にする癖が残ります。

| 問い | 満たす例 |
| --- | --- |
| **読み飛ばすと困るか** | 前提・制約・順序（「**マージすると DB が数分落ちる**」） |
| **目に止まると読みやすくなるか** | 表や長い節の中で、探している行へ導く（「**書き込みが99.6%**」） |

**どちらも外れるなら外す。** 「新規登録の変更内容は数えていないが、**計算で出せる**」の太字は、読み飛ばしても困らず、探す手がかりにもなりません。

**強調は相対的にしか働きません。** 要らないものが混ざるほど、要るものが埋もれます。

## 比喩は、実装の語に置き換えられるかで判定する

**比喩は書き手には分かりやすく見えます。** 動きのある語なので、書いていて筆が進む。ところが読み手は
**その比喩を実装へ翻訳し直す**ことになります。

| 判定 | 例 |
| --- | --- |
| **その語に対応する処理が指させるか** | 「手で配る」→ **指せない**。何を呼んでいるのか書かれていない |
| 置き換えると具体になるか | 「経路ごとに更新処理を呼ぶ」→ **指せる** |

**「配り忘れ」「塞ぐ」「寄せる」「回る」は、どれも動作の実体を隠します。** 何を呼び、何を書き足したのかを
そのまま書けば、同じ長さで通じます。

**用語として定着しているものは比喩ではありません。** 「キャッシュを温める」「フラグを立てる」のように、
その現場で1つの意味に決まる語はそのまま使う（ `plain_language_explanation.md` ）。

**判定は「その語を実装の名前へ置き換えられるか」。** 置き換えられないなら、書き手も何が起きているかを
言語化できていません。

## 語を狩らない。意味で判定する

**表の「例」は手がかりであって、置換の一覧ではありません。** 同じ語が別の意味で使われます。

| 語 | 対象になる意味 | 対象外の意味 |
| --- | --- | --- |
| **効く** | 効果がある（「この対策が効く」） | **適用される・発動する**（「本ルールが先に効く」「 `paths` が効かない」） |
| ただし | 対比が弱いのに置く | 本当に逆接 |
| **すべき** | 聞かれていないのに助言する | 規約として求める |

実際にルール群で「効く」を数えたら、大半が**適用の意味**でした。一括置換すれば、そちらまで壊れます。

**同じ理由で逆向きにも壊れます。** 断定の語を一律に弱めると、実測が裏にあるものまで見込みの話になります（ `base_records_on_measurements.md` ）。

## 名詞で積まず、動詞で書く

**サ変名詞を並べると、主語と述語が遠ざかります。** 「〜の実施」「〜の増加」「〜が問題を提起する」の形は、誰が何をしたのかが読み取りにくい。

```
❌ 世界の人口増加が食料補給の問題を提起している
✅ 世界の人口が増加したので、食料の補給が問題になっている
```

**判定は「誰が何をしたか、1回読んで分かるか」。** 名詞が3つ以上続いたら、動詞へ開けないか見る。

## 読点で息継ぎを作らない

**話すように書くと、声に出す間隔で読点が増えます。** 書き言葉の読点は構造を示す記号なので、息継ぎで置くと**構造を示していない読点**が並びます。

```
❌ 変更履歴の中で、どこが重いのか
✅ 変更履歴の中でどこが重いのか

❌ 書き込みは、詳細より履歴の行が重い
✅ 書き込みは詳細より履歴の行が重い
```

**判定は3つ。どれにも当たらなければ落とす。**

| | 例 |
| --- | --- |
| **外すと後ろの語と繋がる** | `98.5% で、` ／ `2種類あり、時間とは別` （ `あり時間` が1語に読める） |
| **並列の区切り** | `A、そうでなければ B` |
| **文全体が50文字以上** | 読点までではなく、**その文の長さ**で見る |

**落とすのは、50文字未満でこの3つに当たらないもの。** 主題の直後（ `書き込みは、詳細より` ）、
短い条件節の直後（ `差分が無ければ、` ）、逆接・理由（ `点灯するため、` `保存しても、` ）が典型。

**測るのは前の節ではなく文全体。** 前の節で見ると逆転する。実測した9件で、置くと判定されたものの前の節は
**8文字から60文字まで散っており**、落とすと判定された25文字より短いものが両側に現れた。
**文全体なら、置く側の最小51文字と落とす側の最大48文字で分かれる。**

**「長い」を数で決めるのは、そうしないと抜け道になるから。** 実際に感覚で判定して18箇所残し、
2箇所まで落とし、そこから4箇所へ戻した。**書き手は自分の文を読めるので、長さの感覚が読み手とずれる。**

**中止法（ `〜し、` `〜り、` ）は、それだけでは残す理由にならない。** 50文字未満なら落とす。

```
❌ 項目そのものが削がれ、変更履歴に残す項目も見直される
✅ 項目そのものが削がれ変更履歴に残す項目も見直される   ← 繋がらないので落とす

❌ 落ちる原因は2種類あり時間とは別                     ← 「あり時間」が1語に読める
✅ 落ちる原因は2種類あり、時間とは別
```

**機械的に落とすと壊れます。** 実際に1つの文書で24箇所落とし、2箇所を残しました。残したのはどちらも中止法で、外すと後ろの語と繋がるものです。前節と同じで**記号ではなく働きで判定する**。

## 判定のしかた

**書き終えてから、次を機械的に見る。**

1. **各段落の1文目。** 中身ではなく前置きなら消す
2. **太字の数。** 1段落に3つ以上なら減らす
3. **断定している箇所。** 裏に実測があるか。無いなら語尾を推定に変える
4. **読点。** 外して文意が変わらないなら落とす
5. **名詞が3つ以上続く箇所。** 動詞へ開けないか見る
6. **否定を探す。** 「〜ではない」で終わる文と、「〜ではなく、〜」の1文形
7. **拾った否定を、否定した側で判定する。** 読み手が実際に選びうるなら残し、**誰も言っていないなら落とす**

## 禁止する挙動

- 発見や結論の価値を事実より先に宣言すること
- 1段落に太字を3つ以上置くこと
- 「まず」「次に」で作業を実況すること
- 定型の締めを付けること
- **効果を「効く」で断定すること**。実測があるなら数字を出す
- **短い断定文を対句で並べること**。1文へ畳む。片方は他の節と重複していることが多い
- **肯定で言えることに、否定を足すこと**。「A。Bではない」の B は、たいてい A から出てくる
- **否定しか書いていない文を残すこと**。何であるかを言っていないので、読み手が埋めることになる
- **誰も言っていないことを否定すること**。「分離は設計ではなく〜」は却下された仮説を一度持たせるだけ。**否定した側を読み手が実際に選びうるかで判定する**
- **表の例を置換の一覧として使うこと**。同じ語の別の意味まで巻き込む
- **息継ぎで読点を置くこと**。主題・短い条件節・逆接・理由の直後は外しても構造が読める
- **サ変名詞を積んで主語と述語を遠ざけること**。動詞へ開く
- **比喩で動作を言い換えること**。「手で配る」「塞ぐ」は実装の語へ置き換えられない。読み手が翻訳し直すことになる

## なぜ

- 文体は**中身より先に読まれる**。演出が冒頭にあると、そこで読み手の期待が決まる
- 演出は**外したときに残る**。「決定的です」と書いた結論が覆ると、書き手の判断力ごと疑われる
- 強調は**相対的**にしか働かない。全部を強調すると、何も強調していないのと同じになる

## 例外

- ユーザーが特定の文体を指定した場合
- 危険な操作の警告（強調が必要な場面）

## 関連

- `no_ai_slop.md` （量を出さない）: **元は1本だった。** あちらは**量と中身**、本ルールは**表現**。判断材料として正しくても AI っぽい文体、は成立する
- `base_records_on_measurements.md` （記録は実測に基づける）: **断定と推定の語尾の使い分け**はあちらが定める。本ルールは「効果の断定」という型を挙げるだけ
- `concise_first_then_detail.md` （簡潔に）: あちらは**量**、本ルールは**文体**。あちらの「言い換えの反復」は**同じ向きで2度**、本ルールの「要らない否定」は**逆向きで1度**
  **比喩も軸が違う。** あちらと `focus_insights_on_judgment.md` は**装飾として足すな**（量が増える）、本ルールは**事実を比喩へ置き換えるな**（量は変わらず正確さが落ちる）
- `plain_language_explanation.md` （噛み砕いた説明）: **業界で通っている語を使う**のと**長い修飾語を先に置く**のはあちら。本ルールは**機械が書いたように読めるか**だけを見る
- `github_one_sentence_per_line.md` （1文ごとに改行し句点を落とす）: あちらは**改行と句点**、本ルールは**読点**。「読点では折らない」はあちらが定める
- `explain_from_observables.md` （観測できるものから始める）: 本ルールは**名詞で積まず動詞へ開く**、あちらは**開いた動詞を具体にする**（「落ちる」→「ジョブが落ちる」）
