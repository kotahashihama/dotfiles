# AI が書いたと分かる文体で書かない

会話・PR 説明・コミット・レビューコメント・ドキュメント、**こちらが書くものすべて**が対象です。
これは全プロジェクト共通の規約です。

**中身が良くても、文体で読む気が削がれます。** 読み手は1行目で「機械が書いたな」と判じ、そこから先を流し読みします。判断材料として正しくても、読まれなければ届きません。

## 型と直し方

| 型 | 例 | 直し方 |
| --- | --- | --- |
| **発見の演出** | 「決定的です」「見つかりました」「重要な結果です」 | 事実から書き出す |
| **実況** | 「まず〜します」「次に〜を確認します」 | やった結果だけ書く |
| **定型の締め** | 「以上です」「他にあればお知らせください」 | 書かない |
| **強調の乱発** | 1段落に太字が3つ以上 | 段落に1つまで |
| **要らない強調** | 主張の中心を反射で太字にする（「〜が、**計算で出せる**」） | 下記の2つを問い、どちらも外れるなら外す |
| **逆接の演出** | 対比が弱いところへ「ただし」「一方で」 | 句点で切る |
| **助言の押し売り** | 聞かれていないのに「〜すべき」 | 判断材料を出して止める |
| **効果の断定** | 「効く」「効いてくる」「が効果的」 | 実測があれば数字を出す。無ければ推定と分かる語尾にする |
| **対句の反復** | 短い断定文を並べる（「〜しました」「〜変わりません」） | 1文へ畳む。片方が他の節と重複していれば落とす |

**演出は冒頭に出ます。** 本題に入る前にその本題の価値を宣言してしまう。

```
❌ **原因が特定できました。** 索引が `agent_id` 単独しかありません
✅ 索引が `agent_id` 単独しかありません
```

**対句は、書いた側には歯切れよく見えます。** 同じ長さの断定文が並ぶとリズムが出るので、**中身が増えていなくても文章が締まった感じになります**。

```
❌ 素通りする側を絞りました
   挙動は変わりません
✅ この PR では素通りする側をフィルタリングする形で修正しています
```

**片方は他の節と重複していることが多い。** 上の「挙動は変わりません」は影響範囲の節にあり、概要では要りません。

**検査があります。** dotfiles の `scripts/lint_docs.sh` を通すと、`suiko` が `antithesis_repetition` として拾います。手で探す前に回してください。

## 強調は、2つのどちらかを満たすときだけ

**1段落に1つでも、要らない強調はあります。** 密度だけを見ていると、主張の中心を反射で太字にする癖が残ります。

| 問い | 満たす例 |
| --- | --- |
| **読み飛ばすと困るか** | 前提・制約・順序（「**マージすると DB が数分落ちる**」） |
| **目に止まると読みやすくなるか** | 表や長い節の中で、探している行へ導く（「**書き込みが99.6%**」） |

**どちらも外れるなら外す。** 「新規登録の変更内容は数えていないが、**計算で出せる**」の太字は、読み飛ばしても困らず、探す手がかりにもなりません。

**強調は相対的にしか働きません。** 要らないものが混ざるほど、要るものが埋もれます。

## 語を狩らない。意味で判定する

**表の「例」は手がかりであって、置換の一覧ではありません。** 同じ語が別の意味で使われます。

| 語 | 対象になる意味 | 対象外の意味 |
| --- | --- | --- |
| **効く** | 効果がある（「この対策が効く」） | **適用される・発動する**（「本ルールが先に効く」「 `paths` が効かない」） |
| ただし | 対比が弱いのに置く | 本当に逆接 |
| **すべき** | 聞かれていないのに助言する | 規約として求める |

実際にルール群で「効く」を数えたら、大半が**適用の意味**でした。一括置換すれば、そちらまで壊れます。

**同じ理由で逆向きにも壊れます。** 断定の語を一律に弱めると、実測が裏にあるものまで見込みの話になります（ `base_records_on_measurements.md` ）。

## 名詞で積まず、動詞で書く

**サ変名詞を並べると、主語と述語が遠ざかります。** 「〜の実施」「〜の増加」「〜が問題を提起する」の形は、誰が何をしたのかが読み取りにくい。

```
❌ 世界の人口増加が食料補給の問題を提起している
✅ 世界の人口が増加したので、食料の補給が問題になっている
```

**判定は「誰が何をしたか、1回読んで分かるか」。** 名詞が3つ以上続いたら、動詞へ開けないか見る。

## 読点で息継ぎを作らない

**話すように書くと、声に出す間隔で読点が増えます。** 書き言葉の読点は構造を示す記号なので、息継ぎで置くと**構造を示していない読点**が並びます。

```
❌ 変更履歴の中で、どこが重いのか
✅ 変更履歴の中でどこが重いのか

❌ 書き込みは、詳細より履歴の行が重い
✅ 書き込みは詳細より履歴の行が重い
```

**判定は「外すと読み手が困るか」。**

| | 例 |
| --- | --- |
| **落とす** | **主題の直後**（ `書き込みは、詳細より` ）／**短い条件節の直後**（ `差分が無ければ、` ） |
| **残す** | **前の節が長い**／**逆接・理由**（ `動いているが、` `決まるので、` ）／**数値や識別子の直後**（ `98.5% で、`。外すと次の語と繋がる） |

**中止法（ `〜し、` `〜り、` ）は、それだけでは残す理由にならない。** 見るのは**外したとき後ろの語と繋がるか**。

```
❌ 項目そのものが削がれ、変更履歴に残す項目も見直される
✅ 項目そのものが削がれ変更履歴に残す項目も見直される   ← 繋がらないので落とす

❌ 落ちる原因は2種類あり時間とは別                     ← 「あり時間」が1語に読める
✅ 落ちる原因は2種類あり、時間とは別
```

**機械的に落とすと壊れます。** 実際に1つの文書で24箇所落とし、2箇所を残しました。残したのはどちらも中止法で、外すと後ろの語と繋がるものです。前節と同じで**記号ではなく働きで判定する**。

## 判定のしかた

**書き終えてから、3つを機械的に見る。**

1. **各段落の1文目。** 中身ではなく前置きなら消す
2. **太字の数。** 1段落に3つ以上なら減らす
3. **断定している箇所。** 裏に実測があるか。無いなら語尾を推定に変える
4. **読点。** 外して読み違えないなら落とす
5. **名詞が3つ以上続く箇所。** 動詞へ開けないか見る

## 禁止する挙動

- 発見や結論の価値を事実より先に宣言すること
- 1段落に太字を3つ以上置くこと
- 「まず」「次に」で作業を実況すること
- 定型の締めを付けること
- **効果を「効く」で断定すること**。実測があるなら数字を出す
- **短い断定文を対句で並べること**。1文へ畳む。片方は他の節と重複していることが多い
- **表の例を置換の一覧として使うこと**。同じ語の別の意味まで巻き込む
- **息継ぎで読点を置くこと**。主題や短い条件節の直後は外しても構造が読める
- **サ変名詞を積んで主語と述語を遠ざけること**。動詞へ開く

## なぜ

- 文体は**中身より先に読まれる**。演出が冒頭にあると、そこで読み手の期待が決まる
- 演出は**外したときに残る**。「決定的です」と書いた結論が覆ると、書き手の判断力ごと疑われる
- 強調は**相対的**にしか働かない。全部を強調すると、何も強調していないのと同じになる

## 例外

- ユーザーが特定の文体を指定した場合
- 危険な操作の警告（強調が必要な場面）

## 関連

- `no_ai_slop.md` （量を出さない）: **元は1本だった。** あちらは**量と中身**、本ルールは**表現**。判断材料として正しくても AI っぽい文体、は成立する
- `base_records_on_measurements.md` （記録は実測に基づける）: **断定と推定の語尾の使い分け**はあちらが定める。本ルールは「効果の断定」という型を挙げるだけ
- `concise_first_then_detail.md` （簡潔に）: あちらは**量**、本ルールは**文体**
- `plain_language_explanation.md` （噛み砕いた説明）: **業界で通っている語を使う**のと**長い修飾語を先に置く**のはあちら。本ルールは**機械が書いたように読めるか**だけを見る
- `github_one_sentence_per_line.md` （1文ごとに改行し句点を落とす）: あちらは**改行と句点**、本ルールは**読点**。「読点では折らない」はあちらが定める
