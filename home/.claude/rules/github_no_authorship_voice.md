# GitHub の文章で、書き手の帰属を匂わせない

PR 説明・コミットメッセージ・コメントで、**「自分の言葉で」「〜と判断した」のように、誰が書いた・決めたかを匂わせる表現**を使わないでください。
これは全プロジェクト共通の規約です。

## 期待する書き方

- 変更点・理由は**変更そのものを主語**にして書く。「〜という事情があったため、〜に書き直した」のように、書いた人を主語に置かない
- 経緯を書きたいときも「〜と判断し」ではなく「〜のため」「〜という理由で」のように、**帰属の無い接続**にする

## 禁止する書き方

- **ユーザーが自分で書いた・理解したかのような表現**（「自分の言葉で」「自分の判断で」等）。実際に手を動かしているのは Claude で、ユーザーは方向付けと承認をする側なので、書き手を偽ることになる
- 逆に**「AI が書いた」「Claude が判断して」と、本文中で改めて主張すること**。生成者の開示は末尾の Note ブロック（`github_note_generated_by_claude.md`）が担っており、本文中で重ねて書くとその一文だけ書き手が浮く

## なぜ

- **ユーザーの方針とエージェントの実装がどちらも混ざって1つの差分になる。** どちらの言葉で書いても実態の半分しか表せず、文責をどちらかに寄せる表現は不正確になる
- 帰属を書くと、後から読む人が「これは誰の判断か」を気にする必要が生まれる。**変更の中身が伝われば足り、誰が言い出したかは判断に不要な情報**
- 生成者の開示はすでに末尾の Note ブロックが担っている。本文中で重ねて触れると情報が重複し、その文だけ浮く

## 例外

- ユーザーが特定の文面をそのまま使うよう指定した場合

## 関連

- `github_note_generated_by_claude.md`（生成者表示）: **開示の置き場所と文言はあちらが定める**。本ルールは本文中の言い回しを扱う
- `karma_commit_style.md`（コミットメッセージの書式）: 主語・語調の一般規約。本ルールはそのうち帰属表現だけを切り出す
