# 対応したレビューコメントには 👍 を付ける

レビュー指摘に**コードで対応したとき**、その指摘コメントへ `+1`（👍）のリアクションを付けてください。**AI レビュー・人間レビューのどちらも同じ**です。
これは全プロジェクト共通の規約です。

## 付ける対象

**コミットを伴うコード変更で応えたコメントだけ**に付ける。返信の有無とは独立で、返信しない運用（人間レビュー）でも付ける。

| コメント | リアクション |
| --- | --- |
| コードを直して応えた | **付ける** |
| 非対応と判断した | 付けない。理由が伝わらないと誤解になる |
| `[ask]` の質問 | 付けない。答えになっていない |
| 記述の誤りの指摘（PR 説明・doc） | 付けない。コード変更を伴わない |

**「読んだ」の意味では使わない。** 付いていること自体が「直っている」の印になるので、対応していないものに付けると、レビュアーが差分を確認せずに閉じてしまう。

## 付け方

インラインのレビューコメントは、PR 番号ではなく**コメント ID**で指す。

```bash
gh api -X POST repos/OWNER/REPO/pulls/comments/<comment_id>/reactions -f content='+1'
```

レビュー本文（`reviews`）や PR コメント欄（`issues/comments`）へ付ける場合はエンドポイントが違う。

| 対象 | エンドポイント |
| --- | --- |
| インラインのレビューコメント | `pulls/comments/<id>/reactions` |
| PR コメント欄 | `issues/comments/<id>/reactions` |

**まとめて付ける。** 対応が一段落した時点で、対応したコメントを一度に処理する。1 件直すたびに付けると通知が細切れになる。

## なぜ

- レビュアーは**どの指摘が片付いたか**を追う必要がある。返信を全部読まなくても、一覧で見て分かる状態になる
- 人間レビューはこちらから返信しない運用（`no_auto_reply_human_review_comments.md`）のため、**対応済みであることを伝える手段が他に無い**
- 「対応した」と「対応しなかった」が同じ見た目だと、レビュアーは全件を開いて確かめることになる

## 例外

- ユーザーが「リアクションは不要」と明示した場合
- リアクションが運用として使われていないリポジトリ（既存 PR を見て判断する）

## 関連

- `no_auto_reply_human_review_comments.md`（人間コメントへ返信しない）: 返信しない運用でも**リアクションは付ける**。本ルールは返信とは別の手段を定める
- `report_formatting.md`（報告の書式）: ユーザーへの対応表と、GitHub 上のリアクションは別々に必要
- `/resolve-ai-reviews` / `/resolve-human-reviews`: 実行手段。本ルールが土台で、スキルは対象の絞り込み方を持つ
