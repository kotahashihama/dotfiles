# 返信したレビューコメントに 👍 を付ける

レビュー指摘に**コードで対応し、かつその旨を返信したとき**、その指摘コメントへ `+1`（👍）のリアクションを付けてください。**AI レビュー・人間レビューのどちらも同じ**です。
これは全プロジェクト共通の規約です。

**返信していないコメントには付けません。** リアクションもレビュアーへ向けた発信なので、返信と同じ許可のもとで動かす。

## 付ける対象

**コミットを伴うコード変更で応え、その返信を投稿したコメントだけ**に付ける。**両方が揃って初めて付く。**

| コメント | リアクション |
| --- | --- |
| コードを直し、**ハッシュを返信した** | **付ける** |
| コードを直したが、**まだ返信していない** | **付けない** |
| 非対応と判断し、理由を返信した | 付けない。理由が伝わらないと誤解になる |
| `[ask]` の質問 | 付けない。答えになっていない |
| 記述の誤りの指摘（PR 説明・doc） | 付けない。コード変更を伴わない |

**人間レビューでは、返信自体が明示指示制です**（`no_auto_reply_human_review_comments.md`）。指示が出るまでは返信も 👍 も行わず、**会話の対応表で報告するに留める**。

**「読んだ」の意味では使わない。** 付いていること自体が「直っている」の印になるので、対応していないものに付けると、レビュアーが差分を確認せずに閉じてしまう。

## 付け方

インラインのレビューコメントは、PR 番号ではなく**コメント ID**で指す。

```bash
gh api -X POST repos/OWNER/REPO/pulls/comments/<comment_id>/reactions -f content='+1'
```

レビュー本文（`reviews`）や PR コメント欄（`issues/comments`）へ付ける場合はエンドポイントが違う。

| 対象 | エンドポイント |
| --- | --- |
| インラインのレビューコメント | `pulls/comments/<id>/reactions` |
| PR コメント欄 | `issues/comments/<id>/reactions` |

**返信の直後にまとめて付ける。** 返信を投稿したコメントを一度に処理する。1 件ごとに付けると通知が細切れになる。

## なぜ

- **リアクションもレビュアーへ向けた発信です。** 返信を控えている相手に 👍 だけ届くと、こちらが何を発信してよいと判断したのかが揺れる。**同じ許可のもとで動かす**ほうが事故が少ない
- **👍 だけでは、どう直したかを辿れない。** 「対応済み」に見えるのに差分への手がかりが無く、レビュアーは結局全件を開くことになる。ハッシュの返信とセットで初めて一覧として機能する
- 逆に返信があるコメントでは、**どれが片付いたかを一覧で見て分かる**状態になる

## 例外

- ユーザーが「リアクションは不要」と明示した場合
- ユーザーが「リアクションだけ付けて」と明示した場合（返信が無くても付ける）
- リアクションが運用として使われていないリポジトリ（既存 PR を見て判断する）

## 関連

- `no_auto_reply_human_review_comments.md`（人間コメントへ返信しない）: **返信の許可がそのままリアクションの許可になる**。人間レビューでは指示が出るまでどちらも行わない
- `report_formatting.md`（報告の書式）: 返信しない段階では、**会話の対応表だけが報告手段**になる
- `/resolve-ai-reviews` / `/resolve-human-reviews`: 実行手段。本ルールが土台で、スキルは対象の絞り込み方を持つ
