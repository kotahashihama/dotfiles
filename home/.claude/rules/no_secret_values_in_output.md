# 秘匿値そのものを出力しない

API キー・トークン・パスワード・MFA シード・接続文字列などの**値そのもの**を、会話・ファイル・コミット・PR・外部サービスのどこにも出さないでください。
これは全プロジェクト共通の規約です。

**「あるかどうか」の確認に値は要りません。** 存在確認・疎通確認・設定漏れの調査は、値を伏せたまま完結します。

## 出さずに確かめる

| やりたいこと | 値を出す書き方（**禁止**） | 値を出さない書き方 |
| --- | --- | --- |
| 環境変数が設定されているか | `echo $API_KEY` / `${VAR:-未設定}` | `[ -n "$API_KEY" ] && echo set \|\| echo unset` |
| `.env` に何が入っているか | `cat .env` | `grep -o '^[A-Z_]*=' .env`（キー名だけ） |
| 認証が通るか | トークンを貼って `curl` | `gh auth status` 等、値を表示しないコマンド |
| 設定ファイルの中身 | 丸ごと Read して貼る | 該当キーの**有無**だけ報告する |

**`${VAR:-デフォルト}` は値を展開します。** 未設定のときだけ代替文字列が出る形なので、**設定されていれば実値がそのまま出ます**。存在確認に使わない。

## ユーザーから受け取った値に言及するとき

**ユーザーが値そのものを伝えてくることはあります。** その場合も、**こちらから出力するときは伏せる**。

| | 例 |
| --- | --- |
| ✅ | 「いただいたトークンで認証が通りました」 |
| ✅ | 「`API_KEY` を `.env` に設定しました」 |
| ❌ | 「`sk-abc123def456` を設定しました」 |
| ❌ | **先頭数文字だけ出す**（`sk-abc…`） |

**部分マスクも避ける。** 断片でも**照合には使えます**し、「どの値か」を示したいだけなら**変数名やキー名で指せば足ります**。

ユーザーは自分が送った値を知っているので、**復唱に情報量はありません**。会話ログに 2 回残るだけです。

## 出てしまったら

**取り消せません。** 会話ログ・コミット履歴・PR コメントのいずれも、消しても記録は残ります。

1. **値をローテーションする**（鍵の再発行・パスワード変更）。これが最優先で、消す作業より先
2. 記録の削除は二次対応。履歴の書き換えや PR コメントの削除をしても、既に読まれた可能性は消えない
3. ユーザーへ**何が出たか**を伝える。伏せると対応が遅れる

## 機械的な検査は最後の網

`pre-commit` フックや走査スクリプトがあっても、**それは通る経路にしか効きません**。

| 経路 | フックの効き |
| --- | --- |
| フックのあるリポジトリへの `git commit` | 効く |
| `--no-verify` / フックの無いリポジトリ | 素通り |
| PR 説明・Issue・レビューコメント | 効かない |
| **会話への出力** | **効かない** |
| 外部サービスへの貼り付け | 効かない |

**「フックが止めてくれる」を前提に書かない。** 止まったのは助かっただけで、防げたわけではありません。書く側が意識していなければ、フックの無い経路で漏れます。

## なぜ

- 秘匿値は**一度出たら価値を失う**。取り消せず、ローテーションのコストは本人以外にも及ぶ
- 「確認のため」「調査のため」は理由にならない。**値を見なくても確認は完了する**
- 機械的な検査と書く側の意識は**別の穴を塞いでいる**。片方があるからもう片方が要らない、という関係ではない

## 例外

- ユーザーが「値をそのまま出して」と明示した場合（画面に出して確認したい等）。**指示があったときだけ**で、こちらの判断では出さない
- ローカル専用のダミー値・公開されているサンプルキーは対象外。判断に迷えば伏せる
