# スキルは既存の書式に揃え、手を入れたら整理する

`~/.claude/skills/<skill-name>/SKILL.md` を新規作成・改修するときは、**既存のスキルの書式に揃えて**ください。
これは全プロジェクト共通の規約です。

**命名（ `動詞-目的語` のケバブケース）・引数の取り方・`argument-hint` の書き方・整理の手順は `/organize-rules` が持ちます。** スキルを触ると決めたら、そちらを開く。

## 禁止する挙動

- **手を入れたスキルだけ直して終えること**。分割・マージ・削除の見直しまでが1セット
- 委譲先があるのに、その手順を自前で書き直すこと
- 既定の挙動で足りるスキルを新設・維持すること
- 既存 SKILL.md を確認せずに、独自のフォーマットで新規 SKILL.md を作る
- 「良かれと思って」既存フォーマットから外れた見出し追加・順序変更を独断で行う
- LLM が生成しがちな装飾的なリード文・過剰な例示を、既存に無いのに勝手に追加する

## なぜ

- スキルは Claude が実行時に読み込む「手順書」。フォーマットが揃っていると、Claude 側の解釈が安定し、期待どおりに発火・実行される可能性が上がる
- ユーザー（読み手）にとってもメンテナンスコストが下がる。「どの skill を見ても同じ位置に同じ情報がある」状態が理想
- 既存フォーマットは過去の改善の蓄積であり、独自流派で書くとその改善が反映されない
- **足すだけだと必ず増える。** スキルが増えるほど、どれを呼ぶべきかの判断が鈍る
- 定期的な棚卸しは要らない。**触ったときに見れば足りる**
- 穴埋めのスキルは、穴が塞がった時点で役目を終える。残す理由が「消す手間」だけなら消す

- スキルは Claude が実行時に読み込む「手順書」。書式が揃っていると解釈が安定し、期待どおりに発火する
- 「どのスキルを見ても同じ位置に同じ情報がある」状態だと、読み手の維持コストが下がる
## 例外

- ユーザーが明示的に「このスキルは特別なフォーマットで書いて」と指示した場合のみ。
- それ以外は本ルールが常に優先する。
