# 記録は実測に基づけ、推定はそうと分かる形で書く

計測結果・調査結果・仕様の記述など、**後から参照される文書**は、実測とそこから計算したものを既定にしてください。想定値・推定値を書く場面もありますが、**実測と見分けが付く形**で置きます。
これは全プロジェクト共通の規約です。

**並んだ数字は、全部が同じ顔をしています。** 推定が黙って混ざると、読み手はどれが確かなのか判別できず、**文書全体の信用が落ちます**。問題は推定を書くことではなく、**区別が付かないこと**です。

## 対象

「その場で読まれて終わる」ものではなく、**後から引かれるもの**。

| 対象 | 対象外 |
| --- | --- |
| 課題管理ツールの調査・計測ページ | 会話の中での見立て |
| ドキュメント・設計資料 | 検討中の下書き |
| PR 説明・補足コメント | 「たぶん〜だと思いますが確認します」 |
| レポート・申し送り | |

## 3つに分類し、3つ目には印を付ける

**書いた数字を1つずつ「これはどこから来たか」で分類する。**

| 区分 | 例 | 書き方 |
| --- | --- | --- |
| **実測** | ログの値・API の応答・ファイルサイズ・コードを読んで数えた個数 | そのまま書く |
| **実測から計算** | 割合・1件あたり・単位変換・「N 倍」 | そのまま書く。**元の実測値も同じ文書に置く** |
| **推定** | 試算・見積もり・逆算・少ないサンプルからの一般化 | **推定と分かる形にする**（下記） |

**どこから来たか答えられないものは消す。** それは推定ですらありません。

## 推定の明示のしかた

**強いほうから3つ。書く量が変わらないなら上を選ぶ。**

| 手段 | 使う場面 |
| --- | --- |
| **節・表を分ける** | 推定が複数ある。「測定結果」と「見積もり」を同じ表に並べない |
| **列を足す** | 表の中に混ざる。`出どころ` 列に「実測 / 試算」を入れる |
| **語を添える** | 単発。「**試算**」「**見積もり**」「**未計測**」 |

**専門語を選ばない。** 「外挿」は正確だが、読み手が意味を取るのに一拍かかる。**平易な語のほうが印として強い**。

**その文書で別の意味に使っている語も選ばない。** 「想定」を業務上の前提に使っているなら、推定の印には使えない。**同じ語が2つを指すと、読み手が毎回どちらか判断することになる**。

**「約」「前後」は明示になりません。** ぼかし語は不確かさを示しますが、**測っていないことは示しません**。読み手は「測ったうえで丸めた」と読みます。

**推定には根拠を添える。** どの実測値から、どう出したか。式が書けないなら、それは推定ではなく当て推量です。

```
❌ 書けた行数: 約90万行
✅ 書けた行数: 未計測（落ちた段は検索用テキスト）

❌ 47.5万件なら8分前後
✅ 47.5万件なら約8分（試算。7万件までの1件あたり0.957ms × 475,721）
```

## 条件の違う実測を並べるなら、条件を列にする

**同じ指標でも、測った条件が違えば別の数字です。** 1つの表に混ぜると、読み手はどの行とどの行を比べてよいのか判断できません。

**書き手には条件が見えています。** 自分で測ったので、どの行がどの条件かを覚えている。**だから列にする動機が湧きません。**

| 混ざりやすい条件 | 例 |
| --- | --- |
| **オプションの有無** | 返す項目を絞る指定・圧縮・並列化 |
| **キャッシュの扱い** | 温まった状態か、毎回捨てたか |
| **対象の版** | ライブラリのバージョン・スキーマの世代 |

実際に、応答サイズの表で1件あたりが4,605文字と1,497文字の2通りになりました。**3倍の差は条件の違いでしか説明が付かない**と読み手に逆算されて発覚しています。

**判定は「同じ指標の値が2倍以上ずれるか」。** ずれるなら条件が混ざっている合図です。

**手段は推定を分けるときと同じ**（上記）。分ける軸が、実測か推定かではなく**測った条件**になるだけです。**そこから出した平均を境界として断定しない**のは、下記「禁止する挙動」のしきい値と同じ形。

## 語尾でも、断定と推定を分ける

**数値に印を付けても、地の文が曖昧なら推定に見えます。** 逆に、推定を言い切ると実測に見えます。分類は数値だけの話ではありません。

| 裏にあるもの | 語尾 |
| --- | --- |
| **実測、または実測からの計算** | **言い切る**（「〜になる」「〜のほうが大きい」） |
| **実測から導ける** | 言い切ってよい。ただし**元の実測を同じ文書に置く** |
| 試していない・観測していない | **「〜しそう」「〜と見ている」「未検証」** |

**片方へ機械的に寄せない。** 断定の語を一括で弱めると、**実測が裏にあるものまで推定に落ちます**。実際に「効く」を全部「効果がありそう」へ置き換えて、差分ゼロの実測（116秒が0.1秒になる）まで見込みの話にしてしまいました。

**判定は「疑われたとき、何を出すか」。** 出せる観測があるなら言い切る。無いなら推定の語尾にする。**1文ずつ決める。**

## 特に混ざりやすい3つ

| 型 | 例 | なぜ気づきにくいか |
| --- | --- | --- |
| **途中で止まったものの逆算** | 「約90万行は書けた」（数えていない） | **落ちた位置は実測**なので、そこから出した数も確かだと感じる |
| **サンプル不足の一般化** | 「N 以上なら成功する」（境界を試していない）／**「日本語では塊で取れる」（1例しか掛けていない）** | 観測はすべて正しい。**間を試していないこと**だけが抜けている |
| **もっともらしい概算** | 「1行100バイト前後」 | 桁が合っているので、検算する動機が湧かない |

## 考察は書いてよい。言い回しを盛らない

**確実な機序は残す。** 削るのは、**観測より前に出た言い回し**のほう。

| 落とす型 | 例 |
| --- | --- |
| **読み手の行動を示唆する結び** | 「他の段を削っても効かない」「〜すれば軽くなる」 |
| **自分の推論を評価する語** | 「〜が原因を示している」「〜の裏付けになる」「〜の説明になる」 |
| **強めた断定** | 「当てにならない」「根拠にはならない」「決定的」「本命」 |
| **対比の演出** | 「〜と対照的で」「一方で〜」を、対比が自明なところに足す |

```
❌ 変更履歴が9割。他の段を削っても効かない
✅ 変更履歴が9割

❌ 落ちる段が一定でないことが、原因を示している
✅ 落ちる段は一定でない。特定の文が重いのではなく、
   トランザクション全体で積み上がったメモリが限界に達している
```

**下の例で機序は残っている。** 消えたのは「示している」という評価だけ。

**判定は「観測を書いたら消えるか」。** 消えるなら言い回し、残るなら機序。

## 検算のしかた

**書き終えたら、数字だけを拾って1つずつ問う。** 文章として読み返すと、前後の説明に納得してしまい素通りします。

1. 文書中の数値・件数・割合を機械的に拾う
2. 1つずつ「実測 / 計算 / 推定」を答える
3. **計算のものは実際に計算し直す**（記憶で「合っていたはず」としない）
4. **推定のものに印が付いているか**を見る。付いていなければ付ける

**割合や「N 倍」も検算する。** 元の値が実測でも、割り算を間違えれば誤りになります。

## 禁止する挙動

- **推定を、実測と同じ形式で並べること**
- **「約」「前後」を付けただけで、明示したつもりになること**
- **推定に根拠（元の実測値と出し方）を添えないこと**
- **途中で止まった処理の到達点を、逆算して実測のように書くこと**
- **境界を試していないのに、しきい値として断定すること**（「N 以上なら通る」）
- **条件の違う実測を、条件を書かずに1つの表へ並べること**。読み手はどの行とどの行を比べてよいか判断できない
- **1例の観測を、その種類全体の性質として書くこと**（「日本語では〜」「この形式なら〜」）。**数で区切っていないので一般化した自覚が湧かない**が、間を試していない点はしきい値と同じ
- 数値の出どころを**記憶で判断すること**。計算のものは計算し直す
- 検証できていない項目を**空欄で済ませること**。「未計測」と書けば、後から埋める対象だと分かる

## なぜ

- 記録は**後から判断の根拠に使われる**。推定が実測の顔で混ざると、それを根拠にした判断が連鎖する
- **1つ見つかると全部が疑われる。** 読み手には区別する手段が無いので、確かな数値まで確かめ直すことになる
- 一方、**推定そのものには価値がある**。まだ測れないものを見積もるのは仕事のうちで、禁じると判断材料が減る。分けるべきは中身ではなく**見た目**
- 「約」を付けると書き手は誠実に感じるが、**読み手には測ったうえでの丸めに見える**。伝わっている内容が食い違う
- 未計測と書くのはコストが低い。**空欄や推定で埋めるより、そのほうが次にやることが分かる**

## 例外

- **見積もりであることが文脈から自明な文書**（設計段階の試算、見積もり専用のページ）。この場合も**根拠は添える**
- 実測が原理的に取れない対象（本番でしか起きない事象など）。**取れない理由を添える**

- `keep_records_current.md` （変えたら説明も直す）: あちらは**鮮度**、本ルールは**確かさ**。どちらも記録が信用できる状態を保つ
- `no_instruction_echo_in_output.md` （成果物に指示を書かない）: どちらも**記録に何をどう書くか**。あちらは**読み手に要るか**、本ルールは**確かさ**で判定する
- `adopt_tools_with_official_defaults.md` （ツールは公式の既定値から）: **実測から閾値を逆算しない**点が同じ形
- `report_formatting.md` （報告に貼る識別子の書式）: あちらは**会話での報告**、本ルールは**後から引かれる文書**
- `recheck_after_every_revision.md` （書き直すたびに全体を確かめ直す）: 本ルールの「検算のしかた」を、**更新のたびに繰り返す**ことを求める
